## 本轮修复

1. 适配微信 4.x 的 `chat_input_field`、标题叶节点和 Qt 文本接口，避免把标题父节点识别成第二个联系人。
2. 微信 Qt 输入框使用 UIA ValuePattern 写入完整预期文本，随后逐字读回；不使用 Enter，也不改动剪贴板。
3. 监视焦点、标题、文本变化；写入前再次核对原文。写入后结果不确定时不重放、不回滚用户操作。
4. 放大标题截图，排除相邻企业标签；模型未识别标题或识别不符时保留生成结果并停止预填。
5. GLM-4.6V 关闭推理，优先通过 `submit_draft` 数据函数返回结构化结果；不支持或未通过校验的输出不写入。
6. 修复内嵌任务 JSON 中中文场景被转义的问题，末尾再次明确所选场景；对常用节日增加场景关键词校验。
7. 请求串行化；暂时限流最多额外重试一次，遵守 Retry-After 并设置冷却时间。额度和权限错误不自动重试。错误仅显示 HTTP 状态和受限业务代码，不回显服务端错误正文。

## 限制与待验证项

- 当前聊天消息区为空，因此未在真实微信中验证历史称呼推断、关系判断和三次向上滚动。自动回归已覆盖最多四次采集与三次上滚。
- 首次成功任务暴露了“中秋场景生成新年文案”的问题，已修复提示与场景校验。中间复测遭遇服务端 `HTTP 429 / 1305` 时没有写入；间隔后的最终完整链路复测通过。该错误在[智谱官方文档](https://docs.bigmodel.cn/cn/api/rate-limit)中表示平台服务过载，服务可用性仍会影响生成成功率。
- 当前实测只证明微信 `4.1.15.56` 的该单聊与纯文本草稿可用，不代表所有微信版本、富文本草稿或群聊均受支持。
- 2026-11-05 实测时尚未按同名绑定档案。后续按备注复用规则见本文件的 2026-11-05 逻辑验证记录；标题仍不等于唯一微信身份。
- 截图仅在内存中处理；本记录不保存实际聊天截图或联系人姓名。便携版 `data` 目录含个人历史和加密配置，应与程序分发包分开。
