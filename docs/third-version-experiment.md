# 真实微信主流程：第三版

2026-11-12 修正：第三版现已直接替换“生成祝福”页面的“真实微信”工作模式。**没有独立实验页，不需要手动导入截图。** 原演示模式不变。本提交包含主入口替换和逐条提示词示例管理；按用户授权推送到 liguaa/wechat_draft 的 main，不在其他本地检出执行 pull。

## 启动与使用

本机在 `WX_chat-v3` 目录运行 [run.ps1](../run.ps1)，或双击 [试用第三版.cmd](../试用第三版.cmd)。旧启动器名称仅为兼容，不再打开实验页；也不再强制指定独立实验数据目录。默认使用 EXE 旁 `data/`，仍可通过 `WECHAT_DRAFT_DATA` 明确指定自己的目录。不迁移、覆盖或读取其他检出的个人数据库。若之前仅在旧 `data-third-version` 配置 API，默认目录不会自动继承，请重新配置或明确使用原目录。

从 GitHub 新克隆需先安装 .NET 10 SDK 并构建发布，仓库不包含 EXE、SDK、个人配置或密钥。启动前请退出其他托盘中的祝语：单实例限制仍保留。

1. 在“API 管理”配置支持图像输入及 Chat Completions JSON 的服务，启用并明确授权必要截图上传。
2. 回“生成祝福”，关闭演示模式，选择目标微信窗口、场景和当次补充要求。
3. 点击“生成三个祝福候选”或按 `Ctrl+Alt+B`。沿用原来的 UIA 优先/仅 UIA/仅视觉适配器，自动核对会话并采集必要聊天区域，无需手工截图。截图和本地 OCR 的定位限制也仍然适用；第三版理解规则不能修复缺失的本地工具栏模板。
4. 如果称呼未知且适配器支持补充历史，最多上滚 3 次、采集 4 张；不支持时使用当前画面。相同截图停止重复采集。过程中仍核对同一会话、焦点和原草稿，不切换联系人。
5. 未知称呼最终返回原页面：填写本次称呼，或明确选择“不带称呼，生成中性祝福”。用户已确认空称呼的档案直接保留为空，不重新猜测。
6. 生成恰好三条候选后，先明确选择一条。每条有独立的多轮修改分支，“重置”只恢复当前候选的原稿；“重新生成”使用已有提取结果，不重做截图提取，清空分支和选择。提取成功但生成失败可“按已有提取结果重试生成”。
7. 可复制选中文案。要预填，需在开始任务前启用“允许选中候选后预填到微信输入框”，选定候选后再点击“预填当前选中正文”。不会自动选第一条或自动发送。
8. 一次预填尝试后锁定该任务的候选选择与编辑，避免改写已尝试预填的历史；仍可复制。需要新文案请重新生成一个任务，不重放不确定写入。

## 预填安全边界

开始时保留原适配器和原始会话快照，不能用重新读取的同名标题建立新写入权限。原始聊天标识、窗口实例、完整草稿、焦点及本地 OCR 必须继续通过原适配器检查；任务开始时未授权预填或缺少独立标题/完整草稿，之后不能升级为可写。用户确认称呼和选稿期间不自动写入、不继续后台截图。

原始检查最长保留 10 分钟（墙钟和单调计时双重限制），任务操作也受其剩余预算约束。到期、新任务、模式切换、关闭程序或写入尝试后释放适配器；到期不影响已有文案的复制和未尝试预填任务的内存修改。真正写入前仍等待返回原微信并检查完整原文，持久化写入意图后才调用一次适配器追加。结果不确定不重放、不会回滚用户活动。

当前会话固定使用开始时的场景、补充要求、API 配置、档案及截图；修改设置需重新开始任务才生效。提示词/示例是例外，每次模型操作重新加载。近期同联系人/同场景文案上下文仍用于避重复。模型推断、用户输入、直接正文、对方正文、标题证据区分保存，不把推断伪装成自己发出的直接称呼，也不自动修改联系人档案。

加密历史保存任务元数据和选中正文；未选中时不把候选 1 冒充最终文案。候选、完整多轮分支、截图及会话内密钥仅在内存保留，不保证重启恢复。关闭程序不重放未完成预填。

## 替换示例与提示词

左侧打开“提示词示例”，恢复逐条新增、编辑、删除、启停、搜索与状态筛选；编辑弹窗仅保存当前一条，不再整篇覆盖。全部已启用示例会附在第三版提示词后，不按场景/关系筛选、不限三条。生成/重新生成读取新内容，不追溯改变已有候选；多轮修改不重新附加示例。全停用或空列表合法，此时不使用风格示例。

首次从运行时 `examples.txt` 导入输入/输出对，保存到同目录独立的 `examples-library.json`。之后模型优先读这个列表，不再读被替换的原始文本；常规构建发布不覆盖用户列表。每次保存前备份旧列表（首次备份导入文本）到 `example-backups`；外部变更冲突拒绝覆盖。删除前确认，任务期间禁止修改。备份可从打开目录后取回，恢复前先备份现有列表并退出程序。

页面可“打开提示词目录”，也可在结果区域点击“打开提示词与示例目录”。运行时 [提示词目录](../artifacts/app/config/third-version/) 与源码 [配置目录](../config/third-version/) 分开；用户逐条列表及备份不随发布或Git分发；请另行保留备份。提取/生成/修改规则及原始文本的外部修改仍可能被发布覆盖，需自行备份。

| 文件 | 用途 | 要求 |
| --- | --- | --- |
| [examples.txt](../config/third-version/examples.txt) | 首次导入的内置风格示例；没有用户列表时回退使用 | UTF-8 普通文本，至少20字、上限128KiB；输入/输出对可导入成逐条记录；新用户列表最多200条、128KiB |
| [extract.txt](../config/third-version/extract.txt) | 第三版称呼推断规则 | 保留 direct/inferred/unknown 及 JSON 输出约定，至少 100 字 |
| [generate.txt](../config/third-version/generate.txt) | 三候选与重新生成 | 保留恰好三条 candidates 输出约定，至少 100 字 |
| [revise.txt](../config/third-version/revise.txt) | 多轮修改 | 保留 greeting/note 输出约定，至少 100 字 |

保存后下一次操作读取，不用重新编译。文件无效明确失败，不回退旧版。示例语义仍须人工检查。旧JSON范例库仅在演示/兼容模块内部保留，旧管理页已替换，不注入真实微信的第三版生成，也不自动迁移到新文本。

默认通常 100–200 字、2–4 个方括号微信表情，可按当次要求调整。字数下限和表情数是提示词规则，不强行补写。程序仍检查正文格式、占位符、场景、称呼和候选差异。

## 实现和验证

普通 C# + HttpClient，无 LangChain/Agent/Python 服务。[ThirdVersionWorkflow](../src/WechatDraft.Core/ThirdVersion/ThirdVersionWorkflow.cs) 管理原始采集与安全预填；[ThirdVersionService](../src/WechatDraft.Core/ThirdVersion/ThirdVersionService.cs) 管理提取、生成和修改。[TaskCoordinator](../src/WechatDraft.Core/TaskCoordinator.cs) 保留演示与兼容测试，不再是主页真实模式的生成路径。

每个模型操作最多额外重试一次；暂态与格式问题共享额度，429 至少冷却 8 秒并遵守 Retry-After，均受取消与时间预算约束。HTTP 失败尝试也计入实际请求次数。预填不采用模型重试机制。

```powershell
# 项目根目录
New-Item -ItemType Directory -Force .tools/temp | Out-Null
$env:TEMP = "$PWD/.tools/temp"
$env:TMP = $env:TEMP
$env:NUGET_HTTP_CACHE_PATH = "$PWD/.nuget/http-cache"
./build.ps1 -Test -Publish
./run.ps1
```

测试使用替身 HTTP 和适配器，不读取个人配置、不调用真实模型或操作真实微信。构建成功不代表真实识别效果、服务商兼容性或微信版本均已实测。原版工具栏定位失败仍需独立适配，不能把生成逻辑升级说成视觉定位修复。
