# 祝语 微信草稿助手

C# + WinUI 3 Windows 桌面原型。打开单聊后按 `Ctrl+Alt+B`，根据所选场景和聊天截图生成中文祝福；自动追加开启且目标校验通过时，把正文填入输入框。发送始终由用户手动完成。

## 运行

便携构建位于 `artifacts/app/WechatDraft.exe`。整个目录一起保留，双击 EXE，或在项目目录运行：

```powershell
.\run.ps1
```

首次默认进入演示模式，使用虚构联系人和本地范例，不发起 API 请求，也不操作微信。点击“插入已有草稿”，再点“生成并预填草稿”，可以体验保留原文并换行追加。生成过程中修改演示草稿或切换演示联系人，本次会停止追加。

启动使用普通窗口，不自动最大化；没有保存布局时按显示缩放使用约840×740逻辑像素并居中。正常关闭后记住你调整的普通窗口大小和位置，下次恢复；旧的最大化标记不再生效。切换或移除显示器时限制在可用屏幕内。内容较长时，左侧菜单和主内容均可独立滚动，底部提示不会覆盖菜单。

## Git 版本管理

默认分支为 `main`。源码、测试、内置范例、模板图片、文档和构建脚本纳入版本管理；`.gitignore` 排除本地 SDK、NuGet 缓存、编译与发布产物、个人 `data/` 目录、数据库、截图、日志和密钥文件。上传前用 `git status` 和 `git diff --cached` 检查提交范围。

```powershell
git status
git add .
git diff --cached --stat
git commit -m "Describe the change"
git push origin main
```

新电脑克隆后安装 `global.json` 指定的 .NET 10 SDK，再运行 `build.ps1`；首次启动使用独立的本地配置。原电脑的 DPAPI 加密数据和 API Key 不随 Git 上传，也不能直接作为其他 Windows 用户的配置使用。

## 真实微信模式

1. 在「API 管理」页面填写支持图像输入的 Chat Completions 服务地址、相对接口路径、模型名称和 API Key。支持 HTTPS，以及单独启用的本机 HTTP 回环服务。
2. 点击“测试图像能力”。测试只上传自动生成的验证码图片，可能产生模型调用费用。测试图片使用固定分辨率，避免高显示缩放裁掉测试文字。
3. 勾选向该服务上传必要聊天截图的授权并保存。更换域名会清除授权选择。
   如需视觉兜底，另外勾选“允许视觉定位上传完整微信窗口”，并选择“自动 · UIA 优先”或“仅视觉”。整窗定位和复核可能包含联系人列表及已有草稿，旧授权不会自动扩大。
4. 返回主页，关闭演示模式，手动打开目标单聊。微信窗口列表会自动更新；只有一个窗口时自动选中，多个窗口时手动选择，后续更新保留该选择。
   “检查 UIA 输入框”只检查 UIA，不截图、不调用模型。“检查视觉定位”上传微信窗口识别布局并显示彩色框预览，不复制草稿、不填写，无需框选或校准。
5. 首页勾选“生成后预填到微信输入框”，再点击开始或使用快捷键。选项默认关闭，立即保存，并与设置页同步；任务期间不能改变，只对新任务生效。开启后保留原草稿并在末尾追加，不会自动发送。生成期间可以浏览“祝语”左侧菜单；需要采集截图或预填时显示“等待返回微信”，最多等待 30 秒且受任务总预算限制，不主动抢回窗口。返回原聊天后重新核对会话、原草稿及输入焦点，再填写一次。切换聊天、修改微信草稿或转到其他程序仍停止预填。
   预填要求 UIA 能复查当前打开的聊天面板、标题和输入控件，并核对窗口实例及原草稿；仅同名不能通过。支持该面板结构的微信不要求当前联系人一直显示在左侧列表中；旧布局仍要求能读取选中的会话。无法确认时保留生成结果供复制。仅视觉或自动回退到视觉时只生成，不预填。实际服务与模型以「API 管理」中勾选的配置为准，不静默回退到其他模型。

首页仅需选择祝福场景，不再单独选择表达语气。模型结合聊天内容、已保存的关系和当次补充要求决定措辞；想要正式、亲切或朴素一些，直接写入“当次补充要求”。旧版保存的语气选项不再影响新任务。

不再提供独立的 Emoji 勾选项，需要表情时在“当次补充要求”写“加 1–2 个 Emoji”或指定你想要的数量；也可写“不要使用表情”。模型按补充要求处理，未提及时提示默认不使用。旧版勾选设置不再影响生成。

真实微信首页使用单列布局，生成表单与结果占满内容区，不再常驻显示右侧技术说明。点击“检查视觉定位”并通过后才展开定位预览，可随时收起；演示模式仍保留右侧模拟聊天。

微信窗口列表在进入首页、切回助手、启动生成或检查前以及任务结束后自动更新，无需点击刷新，不做空闲定时刷新。列表展开或任务进行时暂停更新，生成/检查期间锁定目标选择；自动刷新仅查询窗口与进程信息，不截图、不聚焦微信、不调用模型。

生成或检查期间，左侧导航保持可用，可查看历史、范例、API 管理或设置。侧边栏显示任务进度，并提供“查看”和“取消”；返回生成页会恢复原任务页，结果不会因换页而丢失，任务也不会被重复启动。进行中的任务固定使用启动时的模型、场景、演示联系人和范例版本，之后保存的配置用于新任务。为避免记录被进行中的任务重新写回，联系人编辑和历史删除暂时等任务结束；API 图像测试也不与当前任务争用请求。UIA 只允许原微信窗口与当前“祝语”主窗口之间切换，不把浏览助手误报为换聊天；实际截图和填写仍要求原微信在前台。在助手中不自动滚动微信，也不抢占窗口。

称呼应来自聊天消息中“你如何称呼对方”，标题、备注和昵称只用于匹配档案，不直接作为称呼。例如你发出的消息中出现“陈老师，最近还好吗？”，才可据此生成“陈老师，新年快乐！”。模型新推断的称呼须附上你发出的消息摘录和截图编号；不能使用对方称呼你的词、引用或转发内容。档案与历史页显示称呼来源及摘录，供你核对。没有依据时生成中性祝福；只生成模式不会为找称呼继续操作微信。

来源不明的旧称呼保留但暂停复用，直到有新的聊天依据或你确认；有聊天依据的称呼可以复用。你仍可在“联系人档案 → 编辑档案”主动填写或确认称呼。已确认且留空的称呼仍保留为空。漏写称呼、来源或消息依据不合格时，使用本任务既有的一次额外请求额度，仍失败则不填写。消息来源和方向依赖模型识别，本地校验不等于独立验证截图文字，须核对展示的消息依据。

自动模式在 UIA 缺少必要控件或初始枚举超时时切换视觉适配器。模型返回布局数据，本地检查坐标、区域关系、标题和遮挡。当前客户端的视觉路径始终只生成：先固定启动时的窗口画面，之后可以移动鼠标、点击或切换窗口，结果只显示在助手里；本次不继续截图或滚动，仅使用该画面的标题和消息，不因开启预填选项而获得写入权限。只有能复查会话的 UIA 路径可以预填，仅支持可完整读取的普通文本单聊。UIA 可补充历史时最多上滚三次。未对任意微信版本承诺兼容。

视觉模式将点击定位与变化检查分开：从编辑画布内部计算较小点击区，与发送按钮留出间隔；整个输入面板继续用于监测，写入前后仍核对完整草稿。“检查视觉定位”预览中的紫框是监测范围，橙色小框和十字是点击候选，红框是发送禁区。找不到可确认的点击区时停止，不改用其他区域盲点。

已移植 `wechat_vision3` 的 DPI 工具栏模板定位思路，直接用 C# 执行，无需安装 Python。两张内置深色图标模板在所选微信窗口内匹配，可靠时显示黄框并辅助视觉模型核对布局；主题或版本不匹配时使用原视觉识别。底层保留视觉滚动、草稿复制和追加实现及回归，但当前客户端不启用这些视觉写入动作，视觉生成不读取草稿或使用系统剪贴板。

已同步 `wechat_vision_v0.7z` 的窗口裁剪与坐标换算更新：模板只匹配所选微信窗口客户区，预览使用窗口内坐标，实际操作统一加上该客户区的屏幕偏移，不重复乘显示缩放。截图尺寸不符时停止；需要继续操作微信时，窗口移动/变形或 DPI 改变也会停止并要求重新定位。只生成已固定的画面不再使用实时窗口坐标。更新包的两张图标模板与原版一致，无需替换。

注意区分原剪贴板与微信输入框：剪贴板里有图片或网页文字可以备份恢复；微信输入框里已有图片或附件时，当前不会自动追加或删除它们，会提示先自行处理附件。

本机微信 `4.1.15.56` 曾通过 UIA 真实预填；2026-11-05 同版本也出现无法读取内部控件的状态。新视觉路径已实现，但不能把旧 UIA 成功记录当成新路径实测证据。当前范围见 [实测记录](docs/real-mode-verification.md)。

2026-11-05 早期火山验证仅使用隔离配置；随后按用户明确指令将正式客户端切换为火山方舟 `doubao-seed-2.1-lite`，再次通过合成图片、祝福和布局选区测试，已重启加载。切换及开发验证未操作微信草稿。测试使用 Agent Plan 专属接口；该套餐对非 AI 工具的直接调用有[使用限制](https://docs.volcengine.com/docs/ark/agent-plan-personal-plan-overview?lang=zh)，本地测试通过不证明套餐适用于后续产品分发或生产部署，持续使用应遵守对应套餐规则。配置和验证细节见[实现文档](docs/implementation.md)。

## 发送后保存实际祝福

真实微信首页新增“发送后自动保存祝福”。选好微信窗口、在「API 管理」页面授权必要截图和整窗定位后，点击“开启当前聊天的发送归档”。随后照常在微信手动发送；程序核对新出现的自己发出的祝福气泡，并保存最终文字，支持生成后改写和完全自写，不要求先运行生成任务。

本次只监听开启时的聊天。切换聊天、移动/缩放微信窗口或检测到遮挡时停止，需重新开启；暂时切回助手时不采集微信。按键发送以点击过编辑区后的 Enter / Ctrl+Enter 为线索，鼠标发送要求在已定位发送区域内完成按下和释放。没有画面变化不请求模型；多条快速发送、持续变化、方向或正文不明确时保留“待确认”，不猜测、不重试微信动作。

“已发送祝福”展示最终正文、联系人、观察时间和状态，支持搜索、复制、人工核对修正、删除及按当前工作区清空。原始生成历史独立保留；“已记录”不表示对方已收到或已读。演示模式可在右侧自己写入文字，点“模拟发送并归档”验证，不发送微信消息或调用 API。

开启时通常调用一次布局模型；每次有变化且可核对的发送线索，用前后两张标题/消息截图调用一次模型，同时转录实际文字和判断祝福。事件监听及每 350 毫秒的本地画面更新不调用 API，不落盘、不读剪贴板、不填写或点击微信。仅在用户主动开启记录期间采集；退出不自动恢复监听。该会话独立于“只生成时固定启动画面”的生成任务。

## 已实现

- WinUI 3 七个页面：生成、历史、已发送祝福、联系人、范例、API 管理、设置；托盘入口与可修改的全局快捷键。
- 演示模式、真实多模态请求、图像能力测试、API 配置和服务域名授权。
- 最多四张上下文截图、最多三次 UIA 上滚、有限请求重试、任务取消和单任务互斥。
- 既有文本保留、换行追加、前后校验、重复触发保护、写入意图持久化和崩溃恢复标记。
- 微信 4.x Qt 输入框通过 UIA 文本接口读回、追加完整预期内容，不产生 Enter 按键；标题截图另提供放大区域，识别不一致则停止写入。
- 自动视觉兜底、强制视觉模式、布局识别与预览；当前视觉路径只生成。首页预填开关与设置同步，UIA 复查会话后才允许单次填写；历史区分生成/布局请求并记录兜底原因。
- 智谱 GLM-4.6V 使用数据函数返回结构化结果、关闭推理；常用节日场景校验、限流退避、额度和权限错误不重试。
- SQLite 记录联系人与历史；敏感 JSON 载荷及 API Key 由当前 Windows 用户 DPAPI 加密。
- 联系人候选与人工确认、历史搜索与清理。
- 祝福范例支持关键词和状态查询、新增、编辑、删除与启停；保存前校验唯一 ID、场景、关系、字数和 `{称呼}` 占位符，并原子写入 JSON。首次修改内置库时在数据目录的 `examples/` 下创建副本，内置原文件不变；选择的自定义 JSON 在原文件保存。允许删除至空库，空库时仍可生成，只是不向模型提供范例。
- 按当前聊天备注复用当前账号分组内的真实联系人档案；兼容旧档案的显示名，连续生成复用同一档案 ID。历史页标记是否复用了档案。

## 原型限制

- 真实微信版本需要逐项实测。自动追加默认关闭；不支持的界面不会尝试坐标盲点或全选覆盖。
- 当前按用户指定规则把聊天标题作为备注匹配名，去除首尾空白后精确查找备注或旧显示名。同账号分组内同名按同一联系人复用；多个匹配时，依次优先人工确认、备注字段匹配、最近更新。历史重复记录不会自动删除，模型只补齐未确认档案的空白或未知字段。
- 截图用可见屏幕区域采集，采集时微信应保持前台且无遮挡。视觉只生成固定启动画面后可切换窗口。默认不落盘；开发客户端明确开启调试模式后可保存本地中间截图，正式构建强制关闭。
- 视觉布局和选区复核上传整窗；祝福生成仅使用标题和消息。模型判断、窗口遮挡采样和图像比对不构成绝对的焦点或身份保证，仍需具体版本实测。
- UIA 预填允许移动鼠标、点击、滚轮、不改动草稿的按键及浏览当前“祝语”主窗口。实际修改微信草稿（即使之后改回原文）、切换聊天或转到其他程序仍停止；等待返回微信超时后保留正文供复制，不在之后重新获得焦点时补写。写前等待短暂的操作间隙，焦点在另一个输入框时不抢占输入。检测到用户滚动后，不再自动补充上滚，也不恢复旧的消息位置。优先复查右侧聊天页面、聊天标题容器、标题及输入控件的运行期标识，左侧选中项滚出列表不再直接阻止预填；面板或控件被替换仍停止。旧布局无法绑定面板时继续要求唯一选中项。这些标识不是永久微信好友 ID，也不能消除所有界面竞态。原剪贴板支持常见图片、HTML/RTF 及多格式文字的内存备份与恢复，期间新复制的内容不会被覆盖。虚拟文件、应用专用对象或超出备份上限时停止剪贴板路径；微信输入框中的草稿仍须为普通文本。
- 源码不预置模型密钥。本机配置由当前 Windows 用户的 DPAPI 加密；历史与密钥所在的 `data` 目录属于个人数据，不应随程序分发。
- 便携版数据保存在 EXE 旁的 `data` 目录；DPAPI 数据仅能由同一 Windows 用户解密。正式安装版可改为用户应用数据目录。
- 第一版固定自然段、120 字硬上限，模型服务参数暂按协议固定。更多厂商协议和高级生成参数可继续扩展。

## 构建与验证

调试开发时，在设置中开启“调试模式”并保存。每次生成、定位检查和图像测试会在程序旁的 `debug/` 下建立独立目录，保存中间截图、模型请求摘要、原始返回、布局及失败日志；历史中的“查看调试记录”可直接打开对应目录。API Key 和认证信息会脱敏。文件可能含联系人、聊天和草稿画面，关闭开关只停止后续记录，已有文件由用户手动清理；不要随程序分发这些文件。

按用户请求查看 UIA 边界时，可使用诊断工具的 `uia-regions <输出目录> [窗口句柄]`，导出当前微信窗口的区域标注 PNG 和坐标 JSON。目标须完整显示在前台；只有一个微信窗口时自动使用，否则须指定句柄。图中区分实际 UIA 标题/编辑控件与程序计算的聊天截图范围，未找到唯一滚动控件时明确标注。此命令不调用模型、不点击、复制、滚动或修改输入框；仅显式导图时将包含聊天画面的图片写入指定目录，不改变普通 UIA 检查的无截图行为。

正式版本使用 `./build.ps1 -Test -Publish -Production`，输出到 `artifacts/production-app/`。该版本在构建时强制禁用调试保存，即使复制了开启调试的旧设置也不会生成中间截图或模型日志；常规加密业务历史仍按正常设置保存。普通开发构建默认也关闭调试，供需要时在界面开启。

需要 Windows x64、.NET 10 SDK。项目优先使用 `.tools/dotnet/dotnet.exe`，否则使用系统 SDK。

```powershell
.\build.ps1 -Test -Publish
```

依赖来自 NuGet 官方源或微软维护的 dotnet-public 镜像，包缓存限制在项目 `.nuget` 目录。若 `.tools/feed` 已收集离线依赖，构建脚本优先使用该目录。发布目录包含 Windows App SDK 运行时；需要 .NET 10 Desktop Runtime，当前电脑已经安装，不要求使用者安装 Visual Studio 或 SDK。

## 项目结构

提示词集中维护在 `src/WechatDraft.Core/GreetingPrompts.cs`。本次提示词贡献的负责文件、原型适配取舍和验证方式见[提示词接入说明](docs/prompt-integration.md)。

| 路径 | 内容 |
| --- | --- |
| `src/WechatDraft.App` | WinUI 3 界面及演示适配器 |
| `src/WechatDraft.Core` | 模型协议、任务编排、数据、范例和正文规则 |
| `src/WechatDraft.Windows` | DPAPI、快捷键、窗口识别、截图、UIA 与受保护粘贴 |
| `tests/WechatDraft.Tests` | 可执行验证程序 |
| `config/blessing_examples.json` | 内置范例源文件 |
| `docs/requirements.md` | 需求文档 |

更新内置范例源文件后需要重新构建，或者在客户端直接选择该 JSON 文件后重载。

模型服务在「API 管理」页面维护。已保存的每组配置单独成卡片，勾选哪个就使用哪个，当前项标记“使用中”，选择立即保存并在重启后保留。点“编辑”可以修改任意一组的名称、地址、接口路径、模型、密钥和授权；保存编辑不改变勾选的使用中配置，修改“使用中”那组则下一次任务直接使用新值。新配置点“＋ 添加 API”创建，保存后需自行勾选启用；新增配置不继承其他配置的密钥或授权，原有单组配置自动保留为“默认 API”。每组可单独测试图像能力、清除密钥或删除；至少保留一组，且不能删除“使用中”的那组。有未保存修改时，勾选、编辑、添加或删除前会提示确认。
