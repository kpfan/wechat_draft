# 第三版本地实验说明

基线：`kpfan/wechat_draft` 的 `main` 提交 `b970472e5947e924ee507211e0ae058e6804777f`。本轮在独立工作目录和 `integrate-third-version` 分支集成，并按用户授权发布到 `liguaa/wechat_draft` 的 `main`；原本地检出不变。Git 仓库只包含源码、提示词、测试和说明，不包含本机构建产物、SDK、个人配置或密钥。

## 启动

本机已经构建，可直接启动；从 GitHub 新克隆后，需先按文末命令构建发布（仓库不包含 EXE 与 SDK，需安装 .NET 10 SDK）。

在本地电脑双击根目录的 [试用第三版.cmd](../试用第三版.cmd)，或运行 [run-third-version.ps1](../run-third-version.ps1)。启动后直接进入“第三版实验”。程序使用仓库内的 .NET 10，不改变系统 .NET 安装。若已有祝语进程（包括系统托盘中的进程），先从托盘退出它：原有单实例保护仍生效。

实验启动器使用 EXE 旁独立的 `data-third-version` 目录保存加密配置、历史，不读取或覆盖旧客户端的数据。首次需要在“API 管理”填写并启用支持图像及 Chat Completions JSON 的服务、模型、API Key，明确授权截图上传。密钥仍按当前 Windows 用户使用 DPAPI 加密，不进入源码或提示词。

## 第一次试用

1. 点击“离线演示”：查看虚构的三条候选、切换和复制，不请求模型、不采集微信、不保存真实历史。离线演示不模拟通用 AI 改写，重新生成和修改需要真实截图及 API。
2. 在 API 管理配置服务、勾选使用并授权截图上传，再回到“第三版实验”。
3. 填写祝福场景与当次补充要求。
4. 推荐先使用脱敏的普通 PNG 私聊截图：点击“导入聊天截图”，选择 1–4 张，总量不超过 12 MiB，再点击“使用导入截图生成”。导入只是本地读取，点击生成后才上传。不要上传无权处理的他人资料。
5. 或选择微信窗口，点击“只读采集当前聊天并生成”，在 3 秒倒计时内手动切回所选微信。复用原来的 UIA/本地视觉适配器，截图范围、编号、本地 OCR 标题、检查标志不改；不自动抢窗口。只采集一次，不自动滚动。截图只在内存中保留。
6. 提取规则采用第三版：自己直接称呼优先，其次明确自我介绍、唯一关系、正文与备注联合证据、合适的显示名称兜底；冲突、引用、第三人及方向不清不得强猜。显示名称并非唯一真实身份，用户仍需检查。
7. 无法确定称呼时先停止在确认阶段。选择“生成中性祝福”，或填写本次称呼后继续；不自动用“朋友”等词填空。填写仅影响本会话，不永久修改联系人。
8. 生成成功后显示三个原始候选。选择一个，输入修改意见，例如“再正式一点”“再短一点”“不要表情”，再点击“按意见修改”。每个候选保存独立修改分支，切换不会串上下文；“重置”只清除当前候选的修改，恢复原稿。
9. “重新生成”复用成功提取的输入，避开原有三条及修改后的文案，成功后清空旧修改分支；不重复上传截图。若提取成功但首次生成失败，可点击“按提取结果重试首次生成”。
10. 选中、修改或复制真实候选时更新本地加密历史中的选中文案。原始三个候选和完整多轮修改记录只在内存中，不承诺重启恢复。重新生成产生新的历史任务。

**第三版入口只生成、复制和保存选中文案，不授予微信预填权限，不发送。** 原“生成祝福”入口仍是云端原有行为，包括原有安全预填检查和旧版字数/称呼规则。全局快捷键仍进入原生成流程，不会偷偷改成实验流程。两者不能并发争用采集及请求。用户等待称呼确认期间不保留任何写入权限。

同一实验会话固定使用开始时的场景、补充要求、服务配置、档案和截图；修改表单或 API 配置后，需要重新点击截图生成才能开始新会话。提示词与示例是例外：每次提取、生成、重新生成和修改会重新读取文件，便于本地实验。

## 自行替换示例与提示词

运行时配置位于发布目录的 [提示词目录](../artifacts/app/config/third-version/)，页面也有“打开提示词与示例目录”按钮。源码对应 [配置目录](../config/third-version/)。实验时改运行时目录；确定保留后，将改动同步回源码目录，否则以后发布可能覆盖实验改动。

| 文件 | 用途 | 修改要求 |
| --- | --- | --- |
| [examples.txt](../config/third-version/examples.txt) | 可自行增删、替换的祝福风格示例 | UTF-8 普通文本；沿用“输入/输出”写法即可；至少 20 字，上限 128 KiB。**不是 JSON 文件，不要求每段作为 JSON 解析** |
| [generate.txt](../config/third-version/generate.txt) | 初次生成、重新生成的规则 | 保留恰好三条 `candidates` JSON 输出约定；至少 100 字 |
| [extract.txt](../config/third-version/extract.txt) | 称呼提取规则 | 保留 `direct`、`inferred`、`unknown` 及输出约定；至少 100 字 |
| [revise.txt](../config/third-version/revise.txt) | 多轮编辑规则 | 保留 `greeting`、`note` JSON 输出约定；至少 100 字 |

不需要重新编译或重启，保存文件后下次操作读取新内容。空文件、无效 UTF-8、过大文件、缺少基本输出约定会明确报错，不静默回退。示例本身是自由文本，其语义、事实是否恰当仍需人工检查；程序不能证明任意示例或提示词是安全正确的。旧“祝福范例”库不注入第三版，避免两套示例互相覆盖。

默认通常 100–200 字、2–4 个方括号微信表情；用户当次要求可以调整。字数下限和表情数是提示词约束，不是为凑字数强制补内容。程序仍检查单段、控制字符、占位符、总大小、称呼开头、常见场景和候选差异，超长或格式错误会拒绝。

## 内部实现与边界

- 普通 C# 服务 + `HttpClient` + JSON，无 LangChain、Agent、额外 Python 服务或服务商切换。
- [ThirdVersionService](../src/WechatDraft.Core/ThirdVersion/ThirdVersionService.cs) 是独立实验 API，不改 [IConversationAdapter](../src/WechatDraft.Core/Models.cs) 的输入协议，不重写 [TaskCoordinator](../src/WechatDraft.Core/TaskCoordinator.cs)。
- 成功提取与后续生成分阶段，未知称呼可以先返回 UI。模型、用户输入、标题、对方自我介绍及档案依据明确区分；推断不包装成自己发出的直接称呼。实验不把推断称呼写回联系人档案，避免旧严格来源语义被污染。
- 每个公共网络操作共享最多一次额外重试，不叠加 SDK 重试；成功提取不会因后续生成失败而自动重做。实际 HTTP 次数包含失败的尝试。配置、授权、HTTP 权限错误、重定向与取消不重试。429 冷却至少 8 秒，并遵守 Retry-After；延迟受本次操作取消和时间预算约束。
- 每次操作有原设置的请求和任务超时预算。用户确认称呼的等待不算网络任务，也不持续采集微信。不同交互操作各自拥有新的有限预算，不把用户思考时间算作超时。
- 保留近期文案/已拒稿上下文，结合本地相似度校验避免近似复制。风格方向随机化不是供应商的采样 `seed`，不保证每次一定生成理想文案。
- 本地 OCR 标题不可由模型重读修正；模型识别的显示名仅供展示，不作为预填权限或永久档案身份依据。
- 原始截图、分支对话和会话内密钥不写入第三版配置、示例或额外日志。关闭程序后分支丢弃；加密历史只保存选中正文及基本元数据。

## 构建与测试

```powershell
# 在项目根目录执行
$env:TEMP = "$PWD/.tools/temp"
$env:TMP = $env:TEMP
$env:NUGET_HTTP_CACHE_PATH = "$PWD/.nuget/http-cache"
./build.ps1 -Test -Publish
./run-third-version.ps1
```

测试采用假 HTTP 响应、合成消息及临时数据，不连接真实模型、不读取个人密钥、不触碰真实微信或剪贴板。构建通过不代表任意服务商、真实截图、微信版本或显示缩放均已验证。真实识别与多轮文案质量由用户下一步实验核对。
