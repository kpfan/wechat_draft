## 1. 当前实现范围

系统提供 Windows x64 桌面客户端。用户手动打开单聊后，通过首页按钮或默认快捷键 `Ctrl+Shift+A`，生成祝福并在条件满足时追加到输入框；发送始终由用户完成。

- UI 使用 C# + WinUI 3，页面由 `MainWindow` 及其分部文件（`MainWindow.Pages`、`MainWindow.Examples`、`MainWindow.ApiProfiles`、`MainWindow.SentGreetings`、`MainWindow.WindowSelection`、`MainWindow.WindowLayout`）和 `Ui` 以代码构建；尚未采用独立 ViewModel 的 MVVM 分层。
- 客户端直接进入微信祝福首页。
- 真实模式支持 UIA 优先、仅 UIA 和仅视觉。本地视觉定位加可替换 OCR 标题支持只生成或检查后预填，不依赖模型定位/标题判断；兼容性以实测证据为准。
- 目标框架为 .NET 10；Windows 平台项目目标为 `net10.0-windows10.0.19041.0`。目标框架不等于全部系统和微信版本已通过实测。

旧配置中的 `demoMode` 由 JSON 反序列化忽略。联系人、生成历史和发送记录保留 `IsDemo` 以识别已有演示数据。界面及真实联系人匹配排除这些记录，升级无需迁移或清理数据库。

## 3. 启动与核心流程

### 3.1 启动

1. `Program.Main` 获取 `Local\WechatDraft.Desktop` 互斥锁，重复启动直接退出。
2. `MainWindow` 打开本地仓库，加载设置，标记未完成任务，按保留天数清理历史。
3. 加载随程序发布的范例库；自定义范例重载失败时保留已加载版本。
4. 创建任务协调器、注册快捷键和托盘，显示首页。

设置页使用模态对话框读取按键及当时的修饰键状态。录到有效组合后关闭对话框并填回表单，Esc、取消按钮或窗口失去激活会结束录制。录制期间收到当前已注册的全局快捷键时，将它交给对话框，避免启动生成。点击保存才更新主键和修饰键掩码。旧设置仅包含主键，读取时沿用 Ctrl + Alt。启用状态下，`GlobalHotkey` 用另一个注册 ID 试注册新组合，保存设置成功后才注销旧组合。试注册失败时旧组合仍有效，保存失败时注销新组合。托盘暂停会注销当前组合，恢复时按已保存的组合注册，侧栏底部显示当前组合或不可用状态。

默认数据目录为 EXE 旁的 `data/`；可通过 `WECHAT_DRAFT_DATA` 指定独立目录。真实接口配置与个人历史不属于程序分发内容。

### 3.2 一次任务

`TaskCoordinator.RunAsync` 取得任务锁后复制设置，并通过 `ExampleService.Snapshot` 固定范例库及其版本（复制范例列表及标签数组）；后续选择与请求使用该快照。UIA 初检或模型等待期间在其他页面修改设置/范例只影响新任务。

```text
首页按钮 / 全局快捷键
  → 保存当次配置，选择微信适配器
  → 获取任务互斥锁，检查场景和服务域名授权
  → BeginAsync：UIA 确认目标；必要控件不可用时切换视觉，或直接选择视觉
  → 视觉使用定位截图和本地 OCR 标题；UIA 按控件结构和原文核对
  → 在当前账号分组查找同备注/显示名档案，命中则复用
  → 选择范例，截取当前消息区，再安全上滚最多两次
  → 一次提交最多三张不同的消息区截图
  → 校验正文和截图标题，补齐未确认档案缺失值或新建档案，保存结果
  → 检查启动时预填偏好及适配器能力；关闭或无法复查身份则只保留结果
  → UIA 若正在浏览助手则等待返回原微信，最多 30 秒，未发出写入意图
  → UIA 再次检查原聊天面板/会话绑定、控件、窗口实例、焦点、用户操作和原文
  → 持久化写入意图 → 写入前再次复查 → 追加一次 → 读回核对
  → 条件允许时恢复滚动位置，保存最终状态
```

`TaskCoordinator` 使用 `SemaphoreSlim` 拒绝同一实例的并发任务。任务共享取消令牌和总时间预算，配置被限制在 10–180 秒。模型请求超时单独限制在 5–90 秒。

### 3.3 发送后归档会话

`MainWindow.SentGreetings` 管理主动开启的独立记录会话和“已发送祝福”页，无须生成任务。`WechatSentGreetingMonitor.StartAsync` 使用本地视觉适配器估算区域，并用 Windows OCR 读取标题，取得冻结画面、客户区几何及进程实例标识；区域不证明单聊。核对实时标题/几何后安装只读鼠标/键盘钩子，不调用点击、输入、复制或发送函数。实际内容核对须明确普通单聊才保存正文。

本地每 350 毫秒在目标前台更新标题和消息画面，PNG 仅在内存中，不采集列表或草稿。鼠标完整点击须位于同一发送区；Enter/Ctrl+Enter 须已有编辑区点击线索，过滤注入输入、长按重复及 Shift/Alt/Win/输入法组合状态。钩子只记事件，不截图或请求模型。最近画面超过 900 毫秒不用于新观察；点击后等待消息变化且两次画面稳定、至少 700 毫秒，最多等待 3500 毫秒。无变化跳过，多次快速发送或持续变化留待确认。

`SentGreetingArchiver` 接收固定前后截图，先保存独立核对记录，再通过 `ISentGreetingModel` 单次请求转录新增祝福并分类。协议所有安全字段必填，不提供草稿函数、旧联系人文案或生成稿。前后标题均须一致，新增自己发出的消息数恰好为一、文字完整、无不确定/失败标记，才保存气泡原文和当前分组联系人引用；普通消息不保存正文。模型判断不是独立身份认证或服务端送达证明。

最多八项内存观察排队，模型请求沿用客户端串行限制。同一观察 ID 不再核对，不同发送即使正文相同也分别保留；不确定、超时或失败不重试。停止或设置修改取消旧会话，切换窗口选择停止；生成/检查期间暂停并丢弃旧基线。核对中删除的记录，迟到响应只允许 UPDATE，不能重新插入。退出清理钩子、计时器及队列，重启将“核对中”标为待确认，不恢复采集或请求。

业务载荷使用 DPAPI；状态为“核对中 / 已记录 / 待确认 / 无需归档 / 人工确认”。页面隐藏无需归档项目及旧版演示记录，支持搜索、复制、人工核对修正、删除及当前分组清空。人工修正单独标记，不覆盖生成历史；沿用保留期限和可选联系人历史级联删除。新增表使用幂等建表兼容旧库，不重写已有载荷。

## 4. 微信会话、截图与上滚

### 4.1 窗口与目标检查

`WechatAdapter.FindWindows` 枚举可见顶层窗口，按进程名 `WeChat` / `Weixin` 筛选。列表保存窗口句柄、标题、进程名和 PID；当前不校验可执行文件路径或数字签名。

任务启动后尝试聚焦所选窗口，拒绝无效或最小化窗口，等待修饰键释放，再通过 UIA 查找：

控件枚举在后台只读任务中进行，等待上限为八秒，并支持取消。超时后不使用迟到结果注册监听或执行输入；底层 UIA 调用本身可能仍未返回，因此通过进程内检查互斥锁限制后续枚举，避免重复堆积。该上限只覆盖初始控件枚举，不代表所有 UIA/COM 调用均可强制中断。

- 唯一可读取的输入框，优先匹配 `chat_input_field`，并使用位置、尺寸和可编辑性条件筛选。
- 唯一聊天标题，优先匹配以 `.current_chat_name_label` 结尾的叶节点；缺少该标识时才回退到位置过滤。
- 会话类型证据与“聊天信息”等单聊相关控件；只有判定为真人私聊才继续。
- 消息区域内唯一可纵向滚动的控件；无法确定时不自动上滚。

`WechatConversationRules` 将控件读取与类型决策分离，`Inspect` 收集证据、`RequirePrivateChat` 统一判定：从会话名叶节点沿 RawView 向上定位类名以 `ChatTitleBarMasterView` 结尾的标题栏容器（最多 12 层，找不到不猜测父容器），收集标题栏及后代类名，并在排除会话名控件及含子文本的容器后解析独立的 `(N)` 叶文本作为群成员数；另检测 `mmui::ChatBrandDisorderPage` 聚合页。类名含 `ChatRoom` 或存在成员数/群聊入口判为群聊，含 `ChatBrand`/`Official` 判为公众号或服务号（无输入框为推送视图），含 `ChatSingle` 且有输入框才是私聊（无输入框为服务通知等）；缺少标题栏或类型特征为未知。文件传输助手、标题末尾有配对括号且人数大于 2（与视觉生成共用 `DraftRules.LooksLikeGroupTitle`）及精确匹配的功能账号（服务通知、微信支付等）直接排除，普通备注包含这些词不受影响。判定还必须存在“聊天信息”/“Chat Info”入口作为第二重证据。群聊、公众号、服务通知、聚合页、功能账号、未知类型及缺少单聊入口均抛普通 `InvalidOperationException` 停止且不调用模型，**不**回退到无法核实会话类型的视觉路径；只有整体控件不可读等 `UiAutomationUnavailableException` 才保留视觉兜底。

UIA 边界为物理像素。输入框、标题与滚动控件的位置/尺寸阈值按窗口 DPI（`WindowLayoutRules.WindowDpi`）归一化为 96 DPI 逻辑像素后比较，避免高显示缩放下误排除；`MessageArea` 截图区域保持物理像素供 `CopyFromScreen` 使用，边距和最小尺寸按缩放换算。

这些属于界面特征判断，不是微信提供的会话类型或好友身份接口。标题可能是备注或昵称；当前按用户指定的业务规则用作备注匹配名，并不表示已取得稳定微信联系人 ID。

`ConversationSnapshot` 在内存中保存会话令牌、标题、原始草稿、`PID:启动时间:窗口句柄` 和 UIA 控件状态。`UiaConversationIdentity` 始终保存标题与输入控件的 `GetRuntimeId()`；优先以唯一可见 `chat_message_page` 及其唯一可见 `content_view` 的运行期 ID 作为 `ChatView`，用 RawView 祖先关系确认标题位于该容器、输入控件位于该页面。存在面板绑定时，复查必须仍是原面板和原控件；允许左侧选中项缺失，但两次都可读且不一致时仍失败，不降级为标题或选中项匹配。无法绑定面板的旧布局继续要求唯一 `session_list`、唯一选中项的运行期 ID 和 AutomationId；该任务不能在选中项消失后临时改换绑定依据。还核对快照属于当前适配器、进程实例、窗口几何及原文。运行期标识不是永久好友 ID。

适配器监视前台、选择、标题、文本和滚动事件。UIA 预填使用 `VisionInputMonitor(stopOnWheel:false, stopOnClick:false, stopOnKeyboard:false, companion:...)`，外部点击/按键只更新活动序号，不直接使任务失效。App 明确传入自身主窗口句柄，适配器确认该句柄属于当前进程后才允许在原微信与该主窗口之间切换；不按窗口标题或任意同进程窗口放行。未提供有效主窗口的底层调用仍保持严格前台策略；转到其他程序持续失效。`UiaTaskChanges` 核对选择事件对应的会话绑定、标题新值、完整原文及初始 ValuePattern 值；相同状态通知允许继续，实际变化或读取失败原子保留首个原因，即使之后恢复也不能重获权限。写入期间继续监视会话和标题，发出输入前的文本/Value 变化停止任务；本程序写入后由完整读回比较确认。外部横向/纵向滚轮另记 `WheelObserved`，消息滚动事件只记用户浏览；本程序标记的输入、纯移动和释放事件不记活动。视觉预填使用同样的活动序号策略，并额外以 OCR 标题及输入面板观察结果决定资格；预填关闭时不监测输入。已处置适配器不能重用。这些检查不能形成无竞态的绝对保证。

`UiaForegroundWaiter` 以约 200 毫秒间隔重新核对原聊天与草稿，等待原微信自然回到前台，最多 30 秒并使用任务取消令牌及总预算；不调用激活或聚焦窗口接口。适配器进度显示“等待返回微信”，日志记录等待、返回及中断原因。`IConversationAdapter.WaitForAppendReadyAsync` 在持久化写入意图前调用，自动兜底转发到当前适配器；默认适配器无需等待。UIA 的 `IsUnchangedAsync` 允许助手在前台时只读复查；`CaptureAsync` 另行等待并在截图前后检查微信前台，不上传助手画面，助手前台不自动上滚或恢复滚动。准备填写后仍复查状态，`AppendAsync` 入口和设置编辑焦点前检查微信前台，实际写入前继续独立复查，不能以等待成功代替最终检查。返回等待超时、取消或会话/草稿变化不建立写入意图，不在稍后返回微信时恢复已结束任务。

`StateChangeReason` 提供具体的人类可读停止原因，由兜底适配器转发给协调器；前台、会话、草稿、窗口及 UIA 读取失败统一进入首次原因记录。`uia_prefill_interrupted` 记录原因码且每次任务只记录一次，不包含原草稿、联系人或窗口标题。UIA 事件回调只更新内存状态，诊断写盘发生在任务复查阶段；最终检查与实际写入之间不新增日志。

会话标识日志及只读 `uia-prefill-check` 诊断记录绑定方式 `chat-view` / `session-selection`、选中项是否可读、失败原因及再次复查结果，不输出原始标识或联系人名字。选中项缺失时，可由原聊天面板及标题/输入控件继续完成复查；两类绑定都不完整、列表或选中项不唯一、控件缺少运行期标识及 UIA 异常仍拒绝预填，不改成仅凭标题判断。SelectionPattern 为空时还检查子项 IsSelected，兼容只暴露项目选择状态的提供者。

首页“检查 UIA 输入框”仅执行会话预检查和监听清理，不截图、不调用模型、不写入草稿、不创建任务历史。该检查与生成互斥，支持取消。错误区分为：没有可访问编辑控件且仅存在外层窗口、未打开可识别输入框、位置/读写条件不满足、候选不唯一或读取超时；不会通过盲点坐标填写来绕过失败。

独立开发导图命令 `WechatDraft.Integration uia-regions <输出目录> [窗口句柄]` 在加载配置或密钥前分支执行。`WechatAdapter.ExportRegionsAsync` 复用同一个 `InspectAsync` 获取实际窗口、标题、编辑控件、可选滚动控件及计算的 `MessageArea`；不调用 `BeginAsync`，因此不聚焦、注册监听或读取并保存原草稿。截图前后核对前台、标题、进程实例和窗口几何，要求窗口完整位于桌面内，并通过窗口层级采样检查遮挡。生成 `UiaRegionMap` 和 PNG，输出到用户指定目录；没有调用模型、复制、点击或滚动。`UiaRegionPreview` 将屏幕物理坐标减去截图原点一次，背景按明确的像素源/目标矩形绘制，固定96DPI图像元数据，避免高缩放将背景缩小而坐标不变；图例标明消息截图范围为计算结果，滚动控件缺失时不画框。这是显式诊断导出，不进入自动生成流程或普通 UIA 检查。

### 4.2 截图和补充上下文

`CaptureAsync` 根据标题栏下边界、窗口及输入框边界计算消息区域，调用 `Graphics.CopyFromScreen` 采集原尺寸消息区 PNG。微信应保持前台、无遮挡。默认仅在内存处理截图，开发调试显式开启时可另存本地诊断副本。

在首个模型请求之前采集消息区，UIA 上滚使用现有滚动控件：

1. 校验会话和原文未变，读取 `VerticalScrollPercent`；已到顶部或无接口则停止。
2. 调用 `Scroll(NoAmount, LargeDecrement)`，等待 220 毫秒。
3. 滚动百分比变化大于 0.01 时继续采集。PNG 与已采集截图重复则结束补充。

上限为两次上滚、三张原尺寸消息区截图，按采集顺序一次发送。检测到用户滚轮或非程序触发的消息滚动百分比变化后，停止后续自动上滚，并跳过结束时恢复初始位置。只有会话、焦点和草稿状态仍符合条件时，才尝试恢复初始滚动百分比。

视觉补图期间若祝语窗口在前台，等待最多 10 秒由用户返回原微信窗口，再复核标题和布局后上滚。超时或条件变化时使用已采集的截图。调试日志记录停止补图的原因，例如前台等待超时、用户滚动、布局变化或消息区像素未变化。

视觉模式采集第一张图之前，以已确认的输入区分界线和右边界为基准，按 DPI 换算到分界线上方 16 个逻辑像素、右边界内侧 1 个逻辑像素。确认该点属于原窗口的消息区右侧窄带后直接点击一次，并在指针未被用户移动时恢复原位置。随后一次提交三次 Page Down 的按键事件。采样满 60 毫秒且连续两帧一致时保存第一张消息区截图，预算约 220 毫秒。未能采集时使用定位时冻结的画面并结束补图。每次发出 Page Up 后立即截图，消息区未变化时每隔最多约 15 毫秒重拍一次，预算约 220 毫秒。接受截图前复核标题、布局和用户活动。日志记录按键、次数、截图尝试次数、耗时和可估算的上翻位移。

若工具栏像素或边线微变使原布局无法直接复用，就重新进行本地定位。只有定位结果与原几何一致，且消息裁剪仍位于标题下方、输入面板上方和消息区横向边界内，才接受截图。

### 4.3 本地定位、OCR 标题与视觉预填

`WechatTemplateLocator` 按当前 HWND 的 DPI 缩放内置双工具栏模板，采用稀疏 NCC、置信度和唯一性校验；`WechatLocalLayout` 使用双锚点与本地长水平边线确定消息/输入分界，分别适应工具栏在编辑区上方或下方的布局。模板或边界不可靠直接停止，不请求模型定位。`VisionWindowFrame` 统一客户区物理像素及归一化坐标，点击时只加一次屏幕原点。初次要求目标前台、完整位于屏幕内、没有外部遮挡，并核对窗口进程实例、尺寸及 DPI。

底部工具栏在客户区下方的全宽范围内匹配。聊天区左边界由底部工具栏位置和 DPI 偏移推算，结合客户区边界、按 DPI 换算的最小宽度、双锚点相对位置和输入分界线校验布局。输入区拉高时，分界线的搜索可延伸到消息区起点下方 64 DIP，距起点不足 80 DIP 的候选仍须在至少 85% 的横向采样位置上有双侧对比度。

亮色和暗色工具栏模板均以 192 DPI（200% 缩放）为基准，匹配时按窗口 DPI 除以 192 缩放。`UISettings` 的应用前景色决定首次尝试顺序。同一微信窗口通过双工具栏和完整布局校验后，在进程内记住使用的主题。缓存键包含窗口句柄、进程 ID 和进程启动时间。缓存命中时优先匹配该主题，失败后试另一套，两次共用同一张灰度图和定位时限。写前需要重新定位时共用该逻辑。调试记录包含首选主题、成功主题和是否命中缓存。

先按原规则选择双侧亮度一致的边线，要求 96 个采样点中至少 82 个通过。没有找到时，可补充确认相邻消息贴住的边线。要求至少 72 个点通过双侧对比，同方向的输入侧对比至少 90 个点通过，两端各 4 个采样点中至少 3 个通过双侧对比。间距超过一个取样间隔的多个补充候选视为歧义。初次定位和写前复查共用这条规则。

前两种证据无法确认分界时，允许用编辑区轮廓补充确认。横线至少有 90 个颜色一致且与输入侧有对比的采样点。两侧须分别在工具栏锚点限定的范围内找到直边和向内转折的圆角。圆角允许抗锯齿引起的亮度差，转弯处内侧笔画的双侧对比须强于直边位置。横向对比距离至少为 2 个物理像素。多个相隔的轮廓候选视为歧义。

匹配样本预计算相对帧宽的像素偏移，以值类型存储。灰度和、平方和使用精确整数累加，相关系数按浮点公式计算。`ExactTitleOcrCache` 仅在当前适配器任务内缓存标题裁剪及成功文字，当前裁剪尺寸和所有像素（不排除光标）完全相同时复用文字；否则调用本地 OCR。缓存访问串行且可取消，不替代当前截图、窗口身份、前台、几何或原草稿核对，也不跨任务使用。

`WechatLocalTitleReader.Default` 持有进程共享的默认 OCR 实现。视觉适配器各自创建标题缓存，默认都调用这个实现。Windows OCR 引擎在首次识别时于现有可取消互斥门内创建，成功后由同一实例持有到进程退出。调用方可以注入其他 OCR 实现。

视觉适配器将 `trackWheelActivity` 设为 `false`。滚轮事件仍记入 `WheelObserved`，不会改变复制、稳定检查与粘贴所比较的活动序号，也不会覆盖最近一次点击或键盘事件。该选项只由视觉预填启用，UIA 保留默认活动计数行为。

`VisionClipboardPoller.ReadAsync` 立即检查取消、外部活动及剪贴板，已更新即返回；未就绪时每约 10ms 只重读一次，最多等待 150ms。`ClipboardDraftRead` 记录更新状态、文字、尝试次数及实际耗时；响应窗口内仍未更新才按用户选择返回推定空值。`ClipboardBusyException` 只表示新复制暂时无法打开，可在该窗口内重读，持续忙碌到超时仍抛错误；来源或非文字格式异常直接停止，不折叠为空。视觉 `CheckInputReady` 仍直接核对窗口和当前修饰键/输入法组合，不恢复连续空闲 120ms 等待；每次读取前后及等待期间都复查活动序号。

视觉写入在移到文末后采一帧作为写前对照。`VisionInputSettler` 观察画面相对对照发生变化且连续两帧稳定，允许光标闪烁及已识别装饰变化，最多等待 500ms。随后读回输入框。祝福在剪贴板上保留到微信用新复制的内容替换它。超时、取消、标题或外部输入变化时停止，已发出的粘贴不会重放。

`visual_draft_copy` 记录实际 `attempts`、`elapsedMs`、`maxCopyWaitMs`；`visual-input-settled` 区分 after-copy / after-paste 并记录帧数和实际耗时，`visual_paste_issued.readbackWait` 为 input-changed-and-stable。先前零等待版本的 inputDelayMs/readbackDelayMs=0 日志属于历史版本。等待过程中仍检查原窗口、标题及本次读取开始时的活动序号，不在等待结束后重置序号来放行用户操作。异步定位/OCR、返回微信的条件等待、取消预算及剪贴板有限恢复策略保留。

`IChatTitleOcr` 是可替换的 Windows 层接口：接收标题 Bitmap 和取消令牌，返回文字，不决定操作。`WindowsChatTitleOcr` 默认使用 Windows 本地中文 OCR，缓存引擎并串行调用。同一视觉行被 OCR 拆成多段时按词坐标合并；真正多行拒绝，未识别到文字时裁掉背景并放大重试。词间距还原真实空格，保留引擎实际返回的大小写和符号，不为匹配猜测修正。英文、Emoji 仍可能错漏；更换 OCR 只需替换实现/工厂参数。

正式视觉 `BeginAsync` 在本地读取并校验 OCR 标题，使用 `DraftRules.LooksLikeGroupTitle` 处理末尾人数大于 2 的群聊后缀。UIA 与视觉生成均把 `Capture.LocalTitle` 用于本地校验，并在模型请求中只声明 `recipient_checked_locally=true`。协调器使用本地标题记录会话，称呼校验仍检查本地标题是否被误作称呼。标题仅是账号范围匹配名，不证明唯一身份。

末尾人数规则要求中英文括号配对，允许 ASCII/全角十进制数字及数字间空白。`LooksLikeGroupTitle` 只对捕获的人数去空白、折叠全角数字并去前导零，继续用数字字符串比较避免溢出，不修改标题本身。`OcrPrefillGuard.ValidateTitle` 在草稿读取前拒绝匹配群后缀，并记录原始 OCR 标题与本地判定；协调器在快照返回后，对独立读取的标题再执行一次前置检查，在联系人匹配、近期历史查询、模型请求及写入意图前停止。模型返回标题的旧兼容只读流程仍有后置检查，不依靠模型声称 single 绕过后缀规则。该规则仍是用户指定的标题人数启发式，不把“没有匹配后缀”当成永久单聊身份。

视觉模式要求原微信仍在前台且用户未操作时才执行 Page Down 和 Page Up。每次翻页前后核对 OCR 标题、窗口及输入面板边界。视觉路径没有可靠的滚动百分比，采集结束保留当前浏览位置。开启预填且监测已就绪时，快照标记 `DirectAppend=true` 和 `OriginalTextRead=false`。写后的 `ReadDraftAsync` 点击安全编辑点，全选、复制并收起选区。读取新剪贴板内容并核对普通文本、来源、标题和窗口。

写后剪贴板未更新，或新复制的文本末尾与祝福不一致时，标记为待确认。视觉路径只验证文末祝福，原文保留状态留空。

`WechatEmptyPlaceholder` 用内嵌公开界面提示模板识别“长按鼠标 语音输入”，不调用模型或 OCR。它只用于输入面板变化比较中的装饰归一化，不参与是否为空的判定。只搜索编辑区左上方限定范围，要求中性灰、背景对比不超过 80、按 DPI 缩放的字形尺寸；按当前对比峰值确定候选边界，在前后两物理像素内以归一化相关系数至少 0.98 核对完整字形，适应提示的亮度渐变。模板只含公开提示字形，不含私人聊天或截图其他区域。

`OcrPrefillGuard` 保存起始 OCR 标题、首个失败原因和一次性写入标记。视觉模式在生成期间定期复查标题，调试模式通过 `VisionInputChangeLog` 以定位截图为对照，记录首次输入画面差异。等待回到原微信时只检查前台和监测状态，回到微信后由 `IsUnchangedAsync` 核对窗口和标题。进入预填前最多等待 30 秒，受任务取消预算约束。等候期间可以修改草稿，从重新定位起到读回结束使用同一个活动序号，点击或键盘冲突会中止。

「强制生成」创建纯视觉预填任务，复用普通视觉生成的 Page Down 首图采集、Page Up 补图、几何复查、重复图过滤及失败回退，最多三张消息区截图。协调器将每张截图标记为跳过标题检查，模型协议要求标题字段为空。此路径跳过 OCR、同一会话复查和联系人档案匹配，历史以「强制生成」标识，收件人核验字段留空。适配器复用窗口、前台、编辑位置及活动保护，使用无标题的一次性写入标记，追加后照常读回文末祝福。启动任务的截图授权、取消、写入意图持久化和不确定写入状态沿用通用流程。

空草稿的面板快照可通过 `VisionRegionSnapshot.CaptureInput` 匹配已知占位提示并排除显隐差异。提示外围约一逻辑像素仅归一化与背景接近的边缘像素。适配器保留同任务识别到的提示区域，用于处理极淡阶段的残留。

协调器先持久化写入意图。`AppendAsync` 用互斥门防并发。写前截图与初次定位截图的两处工具栏裁剪逐像素一致，且在新图重新找到相同输入分界线时复用布局，否则执行完整模板匹配及几何复查。随后核对 OCR 标题，固定编辑点避开工具栏和发送区域。备份剪贴板后，点击编辑点并移到文末，取一帧核对标题，再粘贴一次祝福。写后只核对新复制的文本末尾。不确定写入交给用户检查。

剪贴板每个读/写阶段使用原生多格式内存保护，不跨生成等待占用备份会话。新复制不会被旧备份覆盖。CF_BITMAP 句柄不可读时，仅在存在且验证过边界的独立 CF_DIB/CF_DIBV5 时重建可拥有的位图副本；原始 DIB/PNG 和其他格式字节仍分别保存，不丢弃用户图片。DIB 解码前检查头、色深、压缩、调色板、像素长度及 64MiB/128MiB 上限，不完整数据仍在清空前拒绝。Win32 支持这些格式间转换，见 [剪贴板格式说明](https://learn.microsoft.com/en-us/windows/win32/dataxchg/clipboard-formats)。微信自己执行复制时的系统历史/同步行为不是本程序可完整保证的范围。

`CF_HDROP` 与 `FileGroupDescriptor` 或 `FileGroupDescriptorW` 同时存在时，`FileClipboardCopy` 在打开原生剪贴板前枚举 OLE 来源格式。预检只接受可独立备份的全局内存格式，排除 `FileContents`、索引数据和流式对象。加锁后以剪贴板序列号复核预检结果，再验证路径列表、文件描述数量与大小以及复制方式，并确认来源提供的格式都已备份。备份仍使用原有内存上限和序列号保护。文件路径只在内存中处理。 [Shell 剪贴板格式](https://learn.microsoft.com/en-us/windows/win32/shell/clipboard)

当剪贴板备份因流式文件、应用对象或数据大小上限被拒绝时，仍通过原有会话、焦点及活动核对，移到草稿末尾并发送一批 `KEYEVENTF_UNICODE` 文本事件。该批次拒绝换行和控制字符，不使用复制、粘贴或发送键。UIA 仍读回核对原文及后缀。视觉路径确认画面稳定后标记「预填结果待确认」，由用户核对正文。剪贴板争用和外部修改仍按原有逻辑中止，部分或不确定写入不会重试。 [Win32 Unicode 输入](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-keybdinput)

OCR 与图像处理默认在内存进行，仅开发调试显式开启可保存本地过程；`visual_draft_copy` 记录 `clipboardUpdated`、`assumedEmpty`、复制字符数量及规则名称，不再产生选区或首尾光标检查裁剪。正式构建强制禁用中间结果。`LayoutApiCallCount` 始终 0。旧模型布局协议仅供隔离兼容诊断，生产适配器不依赖模型客户端或密钥。发送归档仍独立使用 OCR 基线及发送前后内容核对。

开发调试通过任务绑定的 `VisionInputChangeLog` 保存首次输入差异的 `input-baseline.png`、`input-changed.png` 和 `input-change.json`。差异图用于诊断。`visual-prefill-layout-checked` 记录写前布局复查耗时及是否复用，`visual-clipboard-backup` 记录备份耗时，`visual_draft_copy` 分别记录读回时点击、发快捷键和轮询耗时。输入冲突日志仅记活动类别和序号，正式模式及关闭调试时跳过中间结果保存。

## 5. 模型协议与内容规则

真实生成请求携带场景、补充要求、档案中的关系和称呼等生成字段、至多三条范例及原尺寸消息区 PNG。模型结合聊天与确认关系选择语气，Emoji 服从补充要求。标题、档案匹配名和草稿留在本地。称呼仍须来自已确认档案或用户发出消息的直接证据。范例 schema、唯一 ID 和语气标签保留，标签不参与偏好加权。

春节和元旦共用加密设置中的 `ZodiacYear`。空值使用系统公历年份所对应的生肖，下拉框仅列出十二个生肖年，选中其他生肖时立即保存。生成仅为这两个场景追加生肖指令，明确所选生肖优先于范例或聊天历史里的生肖。元旦保留公历节日语义。

内置和自定义场景通过模型提示指导正文生成。场景用语不触发本地拒绝或重试，预填仍须通过正文格式、称呼和会话核对。

`MainWindow.Examples` 提供关键词/状态查询、新增、编辑、删除及启停。编辑保持稳定 ID，场景支持顿号或逗号分隔，多关系通过复选框选择；保存前由 Core 统一校验。`ExampleService` 先验证完整候选库并序列化，再通过同目录临时文件替换目标，成功后才更新内存库、有效路径和内容哈希；失败保留原库。空数组是有效范例库，选择结果为空时仍可生成。首次修改内置文件时，App 先把当前有效库复制到 `WECHAT_DRAFT_DATA/examples/blessing_examples.json`（默认数据目录同理）并保存路径，再执行变更；已选自定义 JSON 原位保存，导入或重载失败不会改写配置路径。

匹配档案通过 `stored_contact` 传入关系、身份、称呼及 `confirmed` 标记。`confirmed_contact` 保留给确已人工确认的档案。提示词要求优先使用已有信息，当前会话标题由本地读取和核对。

生成提示词要求按消息方向和时间顺序识别对方是否在当前这轮交流中先送来祝福。确定时，正文依次写可靠称呼、简短致谢和本次祝愿。身份线索来自对方明确自述或双方直接交流，并用于调整语气和祝愿重点。称呼仍通过现有的消息依据校验，致谢和身份的语义由模型判断。

请求另带 `salutation`：可复用称呼 `required_address_term`、已知时包含、正文开头位置，以及是否允许依据当前聊天确定新称呼。`Contact.AddressTermSource` 默认为 `unknown`，可为 `user` 或 `chat_message`；`AddressEvidence` 保存来源、说话方、最多160字符的短摘录和截图编号。`UsableAddressTerm` 仅接受用户填写/确认或有 `chat_message/self` 消息依据的记录。协调器与客户端均经 `ContactForGeneration` 隔离来源不明的旧称呼，保留名称用于匹配但不把旧称呼送入 `stored_contact` 或强制称呼偏好。旧记录不删除；无新依据时只保留候选，有新有效依据且未确认时才替换，已确认字段保持不变。新增字段存入原有加密 JSON，无需改 SQLite 表。

`stored_contact` 只传已有的有效称呼及来源，完整 `AddressEvidence` 留在本地档案和历史。历史任务仅用于本地查阅。生成流程直接使用通过校验的本轮模型正文，省去历史文案查询、相似度比较与判重改写。

模型提示禁止由标题、备注、昵称直接推断称呼，仅允许从用户发给对方的直接消息确定，排除对方称用户、引用、转发和第三人称。响应增加可空 `address_evidence`，GLM 数据函数 schema 同步增加；新非空称呼须有 `source=chat_message`、`speaker=self`、含该称呼及上下文的短摘录和已提供的 `capture_id`。客户端和协调器均调用 `ValidateSalutation`，检查来源、说话方、摘录和截图关联，以及正文开头；即使 `address_term` 为空，也拒绝明显把已知标题接逗号、冒号或你好/您好的称呼开头。可靠旧称呼可以复用其历史依据，不要求旧截图编号出现在本轮。已确认且为空时不采用新猜测。校验不合格使用任务既有一次额外请求额度，持续失败不更新档案、不创建写入意图。消息方向和摘录真实性仍由模型判断，本地不是 OCR 交叉核验，不能将枚举/包含关系校验视为事实证明。

联系人和任务历史保存称呼来源与依据快照，界面显示原消息摘录、方向及待核对提示。用户主动修改称呼时标记 `user` 并清除旧消息依据；未修改且未确认的旧候选继续待核对。`WechatDraft.Integration salutation-status <数据目录>` 仅输出真实档案及不同来源的数量，不输出姓名、消息摘录或密钥。正文仍受长度和格式校验。

- 使用 Bearer 认证，默认禁止 HTTP 重定向；远程地址要求 HTTPS，本机 HTTP 回环需显式启用。接口路径必须为相对路径。
- 每次生成请求最多三张图、总计 12 MiB。响应体最多 1 MiB。
- 对 `open.bigmodel.cn` 的 `glm-4.6v*` 模型关闭推理，并提供 `submit_draft` 数据函数；函数只返回数据，不执行发送或操作。
- 对 `ark.cn-beijing.volces.com` 的 `doubao-seed-2.1-lite` 显式关闭推理，避免短识图请求的输出预算被推理占用；继续使用通用文本 JSON 协议，不附加智谱专属函数。其他服务和模型不受此规则影响。
- 响应接受文本 JSON，或唯一且名称正确的函数参数 JSON；拒绝多个函数结果、未知函数和明确被截断的结果。
- 解析后校验响应版本、关系类型、正文非空、无换行或控制字符、无未替换变量，并对常用节日做关键词校验。正文长度由 `extra_requirement` 指导模型，请求和本地校验均不规定固定字数。
- 首页不再提供独立 Emoji 勾选项，补充要求的占位提示包含“加 1–2 个 Emoji”。`AppSettings.AllowEmoji` 移除，旧加密配置中的 `allowEmoji` 反序列化时忽略，再保存时不带回；请求不发送 `allow_emoji` 或固定数量策略，只传 `extra_requirement`。系统提示要求是否使用表情及数量遵从本次补充，未要求时默认不使用；不固定最多两个，也不在本地添加、移除表情或按表情数量触发重试。表情与其他自由文本要求一样属于模型指令，未增加语义强制校验。
- 真实生成要求识别出标题，与所选适配器快照标题去除首尾空白后完全一致；UIA 路径快照来自控件，视觉路径来自初始布局图像识别。视觉重复识别并非独立的稳定身份认证；缺失或不一致仍停止预填。

模型请求串行执行。正常生成一次提交采集好的截图，暂时网络故障及模型格式或正文校验错误共享一次额外请求机会。HTTP 429 至少冷却八秒，并参考 `Retry-After`。已识别的智谱额度或权限错误不重试。非成功响应只提取受限业务错误码，不回显服务端错误正文。

## 6. 追加、状态模型与中断恢复

### 6.1 原文保护与写入

`DraftRules.Append` 将原字符串与祝福直接拼接，保留已有空格与换行。

首页预填复选框与设置页共用 `AppSettings.EnableLiveAppend`。新配置默认仅视觉、`default` 工作区、`Ctrl+Shift+A`、历史保留 90 天并开启预填。载入已保存配置时沿用存储值，缺失字段使用旧版默认值。首页切换先保存配置，再更新内存及按钮；失败恢复勾选并提示。任务期间禁用开关；协调器与适配器使用启动配置副本，协调器在写入意图前再次检查真实任务偏好和 `CanAutoAppend`。适配器的 `AutoAppendUnavailableReason` 经自动兜底转发；无法确认目标或关闭预填时保留正文及具体原因，不创建写入意图。

UIA 写入前重新核对目标、输入焦点和完整原文。协调器先保存 `AppendAttemptId` 及“写入中”状态，保存失败时停止写入。当前 Qt 输入框通过 `ValuePattern.SetValue` 写入“原文＋正文”。读取时可同时使用 `TextPattern`，两种非空结果不一致或发现非文本对象时停止。

写入阶段先等待250毫秒无新操作的间隙，最多四轮；中断、持续输入或未完成组合时不写入。焦点已在其他 Edit 控件时不将其抢回；允许从非编辑区域聚焦已验证的聊天输入框。聚焦后重新核对会话/原文，实际写入或粘贴前再核对目标前台、输入法状态、输入控件焦点和活动序号；新的操作可能使本次转为手动处理，但不会仅凭此前点击或按键取消生成。活动序号不保存键值或输入历史；原草稿修改仍停止，不能自动把用户中途新输入视为已授权原文。

其他受支持输入框保留剪贴板追加路径：通过与视觉模式相同的多格式备份机制保护原剪贴板，带本程序输入标记的 `Ctrl+End` 后复查并粘贴追加后缀；无法安全备份时停止。使用本进程的消息窗口持有剪贴板，不借用微信窗口作为所有者；恢复前在锁内检查序列号，避免覆盖用户新复制的内容。

UIA 路径写入后最多读回十二次、每次间隔 100 毫秒，统一 CR/LF 表示后与完整预期文本比较。成功时记录 `OriginalPreserved=true`；无法确认时不重复写入、不清空或回滚。代码不点击发送，也不注入 Enter 或发送快捷键。

### 6.2 持久化状态

当前不是独立枚举状态机。`TaskProgress` 用于界面阶段提示；`TaskRecord` 用两个字符串字段分别记录生成和预填结果，修改状态名称时需同时检查界面、恢复逻辑与测试。

任务成功、失败、取消和超时均发送终态进度。窗口预检查失败显示“检查失败”，后续异常显示“处理失败”，不会继续显示上次的“检查会话 / 8%”。进度 100 表示该次执行已结束，不表示生成或写入成功。新任务开始时清除旧通知并重置进度，独立检查也明确显示通过、失败或取消。

| 字段 | 当前状态及含义 |
| --- | --- |
| `GenerationStatus` | `未开始` → `进行中` → `成功` / `失败` / `取消`；启动恢复可标为 `中断` |
| `FillStatus` | 初始为 `未尝试`；发出写入前为 `写入中`；读回成功为 `已预填` |
| `FillStatus` 的停止结果 | `待手动处理`：追加关闭、检查失败或取消等；`未预填`：写入意图前发生异常；`预填结果待确认`：意图已保存后的异常、取消或读回无法确认；恢复时也可能标为 `中断` |

生成成功后，即使标题核对、预填或后续步骤失败，也保留“生成成功”及正文。预填结果不代表消息已经发送。

应用启动时，`RecoverInterrupted` 检查没有 `CompletedAt` 的历史：存在写入尝试标识的任务标为“预填结果待确认”，其他标为“中断”；生成结果已成功的保留成功，其余标为中断。只修正记录，不恢复或重放微信操作。

### 6.3 首页布局

真实微信首页使用单列生成表单与结果，不再创建常驻技术说明侧栏。`_visionPreviewCard` 默认折叠，位于表单和结果之间；仅独立视觉检查成功加载图像后展开，并提供收起按钮。检查开始先隐藏旧卡片，失败/取消不留下空白占位；重新进入首页重建为折叠态。设置页保留工作区、识别方式、快捷键、历史保留、自动追加与调试开关，并提供跳转按钮；模型配置与授权在「API 管理」页维护。

`MainWindow.WindowSelection` 仅在窗口激活、进入真实首页、任务/检查开始前及结束后更新列表，不创建定时器或空闲轮询。下拉展开、非首页、生成/检查运行和关闭中均跳过。移除手动刷新按钮，零候选时提示打开微信后自动识别；唯一候选自动选择，多候选不猜测。`WechatWindowSelection` 按句柄、PID、进程启动时间保留有效选择，不按标题绑定；新对象必须取自实际 Items，列表值相同时不重建，避免闪动或丢选。进入任务后禁用选择器，适配器继续使用启动时绑定的目标。`FindWindows` 只枚举可见微信进程窗口，记录进程启动时间并跳过退出/不可读的实例，不调用UIA、截图或模型，不激活窗口。选择保留仅在本次客户端运行中，不将句柄作为永久身份保存。

`MainWindow.WindowLayout` 取消固定1240×860物理像素启动，每次明确恢复为普通窗口。`AppSettings.WindowLayout` 缺失时使用约 1360×1240 DIP，按显示器当前 DPI 换算并居中，默认尺寸上限为工作区的 90%；旧 `Maximized` 字段仅保留兼容，不决定启动状态。正常关闭时保存最后跟踪到的普通窗口 DIP 宽高和屏幕像素位置，新保存的 `Maximized=false`；`AppWindow.Changed` 仅在还原状态采集边界，最大化、最小化及关闭过程不覆盖记录。恢复先选择原位置最近的显示器，再以该屏当前 DPI 换算尺寸，`WindowLayoutRules` 校验并夹在工作区内，过小的保存尺寸在空间允许时扩大到 1280×1200 DIP，尺寸下限至多占工作区的 90%。窗口状态只是界面偏好，保存失败不阻止退出或改变输入决策；它与现有设置同存加密 JSON，不迁移数据库表。侧边栏把标志、导航和说明放入受高度约束的独立滚动区，快捷键/版本留在底部；主内容显式开启纵向滚动。

### 6.4 任务期间的页面导航

`MainWindow.TaskNavigation` 使导航按钮始终可用，不受任务忙碌状态控制。`Navigate` 离开首页前保存场景和补充要求；任何 `_runCancellation` 活跃期间，`ShowHome` 复用 `_runningHomeView`，不重新创建目标选择或结果控件。

侧边栏底部提供常驻任务卡片：运行中展示阶段和百分比，可查看原任务页或取消；任务在其他页面结束后保留完成提示，回到首页才收起。进度、通知和最新结果独立于当前展示页保存，完成回调更新原任务页，不跳走或重建用户正在编辑的设置页。结束时若用户已回到首页且设置在任务中更新，重新渲染最新设置，并恢复结果、进度及通知，避免预填开关与下一次实际配置不一致。

`SetBusy` 继续锁定开始/检查、目标窗口和首页预填开关，保持单任务。历史删除/清空、联系人增改删由 `IdleAction` 控制，确认框返回后再次核对任务空闲，防止当前任务覆盖用户修改或重建已删除记录；任务结束自动恢复这些操作。独立 API 图像测试在已有任务期间不发出请求；API 选择、配置保存、设置与范例管理保持可用，修改作用于后续任务。浏览助手主窗口不会使 UIA 任务因前台变化直接失效；返回微信后复查原聊天与草稿再填写，其他程序、聊天和草稿变化仍停止。

## 7. 数据保存与联系人边界

SQLite 文件为 `drafts.db`，包含 `settings`、`contacts`、`tasks`、`sent_greetings` 四张表。业务对象序列化后经当前 Windows 用户 DPAPI 加密存入 `payload`；API Key 字段也单独受 DPAPI 保护。记录 ID、scope 和任务时间索引等元数据并非整库加密。

| 数据 | 主要保存内容 |
| --- | --- |
| 设置 | 接口地址、模型、受保护密钥、授权 origin、场景、补充要求、模式、追加开关、超时、范例路径、保留天数和快捷键 |
| 联系人 | 内部 UUID、显示名、业务匹配备注名、名称来源、关系、身份、称呼及其来源/消息依据、确认状态、名称匹配状态、scope、更新时间、演示标记 |
| 任务历史 | 联系人引用及当次快照（含称呼来源/依据）、`ContactReused` 复用标记、场景、正文、时间、模型/服务 origin、两类状态、错误、截图/上滚/API 次数、范例版本、写入意图、原文字符数与校验结果 |

完整原始草稿不写入任务历史，截图也不主动落盘。历史默认保留 90 天，配置为 0 时留到手动清理；联系人档案单独管理。

### 历史页读取与列表性能

`HistoryPageView` 使用编译 XAML 的 `ListView` / `ItemsStackPanel`，直接放在剩余高度为 `*` 的 Grid 行中，不再套用主窗口的外层 ScrollViewer。列表只实现附近条目的容器，详情合并到可展开区域；`HistoryItem` 保存展示数据和绑定到该条记录的命令，不在 `_idleActions` 中长期保留每个列表按钮。[Microsoft 的 ListView 文档](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/listview-and-gridview)说明该面板支持虚拟化；有界布局与数据分页配合使用。

SQLite 增加 `(scope, created DESC, id DESC)` 组合索引，不增加业务表或明文搜索字段。`ReadHistoryBatch` 通过时间及 ID 游标分页，用参数限定工作区，时间相同时仍稳定排序，不使用随列表增长的 OFFSET；读取时逐条检查取消。既有 `History` 接口仍供恢复、删除联系人关联和其他业务调用使用。

`HistorySearchSession` 在 `Task.Run` 中通过信号量串行访问页面缓存，按 64 条扫描 DPAPI 加密记录，记录只有被读取时才解密，并缓存对应搜索文本；一次按所选页大小（20 / 40 / 80，默认 40）返回匹配结果及是否还有下一页。`HistoryFilter` 将关键词、联系人/场景包含匹配、预填状态精确匹配、本地开始日期的闭区间和模式筛选组合；空条件不限制，倒置日期报错。所有条件均在相同工作区的后台缓存扫描中执行。查不到或匹配较远时继续扫描本工作区；后续关键词复用已读记录，不反复解密。取消的半批次不推进游标，不因取消丢失数据。缓存仅存当前页面内存，离开后取消请求并释放，不写入明文索引。

搜索输入采用 250 毫秒防抖；页面使用请求序号与取消令牌拒绝旧搜索和旧分页的迟到结果。首页、上一页、下一页通过匹配结果偏移量查询并替换本页条目，不再滚动追加；页大小及筛选变化回到第一页，支持重置条件。为保留首次有界解密，扫描未完成时不展示总页数，扫描结束后给出精确总数。刷新、删除/清空及进行中的生成任务结束后新建查询会话，保持当前筛选；删除保留当前页，空页回退最后有效页，其余刷新回到第一页。删除与清空仍需确认，确认返回时再次检查任务空闲和页面有效；页面级错误本地显示，不替换用户当前页面。`SelectNavigation` 和窗口关闭负责取消历史页，历史列表不创建空闲轮询、模型请求或微信操作。

### 7.1 按备注查找与复用

`LocalRepository.FindContactByName` 解密当前 scope 内的档案后查找。匹配规则为：

1. 以当前适配器读取的聊天标题作为备注匹配名，仅去除首尾空白；视觉路径标题来自布局识别。
2. 只查当前 `AccountScope` 且 `IsDemo=false` 的记录，比较 `RemarkName` 或旧档案的 `DisplayName`，使用区分大小写的完整字符串匹配，不做模糊匹配。
3. 多个匹配按 `Confirmed` 优先、备注字段精确匹配优先、`UpdatedAt` 降序排序；完全并列时按内部 ID 顺序稳定选择。旧重复记录不删除，不迁移历史引用。
4. 命中时，在模型调用前传入已有档案并选择相应范例；任务记录 `ContactReused=true`。生成与标题核对通过后保存同一个内部 ID，连续生成不再增加联系人。
5. 未确认档案只补齐 `unknown` 关系或空白身份；来源合格的非空称呼保持，来源不明的旧称呼不用于生成，只有新有效聊天消息依据才能替换。没有新依据时旧候选保留。已确认档案保持所有字段值，包括留空和 `unknown`。
6. 未命中时，在生成与标题核对通过后新建记录：`Confirmed=false`、`BindingStatus=name_match`，显示名和备注以当前标题保存，`NameSource` 仍为 `chat_title`。旧档案的备注为空时补入匹配名；不将自动复用标为人工确认。

即使之后未预填，档案也可能已更新或新建；标题核对失败时不会更新档案。联系人页支持按备注或显示名搜索，历史页显示档案复用标记。现有 SQLite 表结构不变；旧 JSON 缺少复用标记时为 false，缺少称呼来源时为 unknown，消息依据为 null，不自动推定有可靠来源。

`AccountScope` 默认是 `default`，是本地数据分组，不是自动识别出的微信登录账号。同一分组内实际不同人使用相同备注时，也会按用户指定规则复用；改名后需同步管理页的备注/显示名，否则按新名称建立档案。内部 UUID 仅标识本地记录，当前仍未取得微信号或稳定好友 ID。

## 8. 安全约束、已知限制与验证

- 模型、截图和范例提供的数据不作为脚本或键鼠指令执行；用户必须自行检查并手动发送。
- 调用前核对用户配置的服务 origin 授权。该设置表示用户允许上传必要截图，不等于腾讯平台授权，也不自动证明涉及第三人信息的数据处理合规。
- UIA、界面特征与视觉识别均可能随版本和布局失效。新增视觉兜底不保证一定可用；模型、坐标、焦点、剪贴板来源或全文核对不通过时停止。
- 检查和写入之间仍存在系统调度及用户操作的时间窗口；读取不到可靠前提时应停止，不能以重试写入掩盖不确定性。
- 日志、截图、密钥和个人数据库不应进入提交或分发包；错误日志变更须检查是否可能泄露聊天或密钥。
- 2026-11-05 的实测覆盖微信 `4.1.15.56` 单聊纯文本和已有草稿保留，详见[实测记录](real-mode-verification.md)。真实历史上滚和历史称呼推断尚未实测；逻辑回归不能替代真实界面验证。
- 2026-11-05 同一微信版本出现无法读取内部控件的状态；该状态下 UIA 预填不可用。新增视觉路径须独立实测，此前 UIA 成功不能作为视觉兼容证据。
- 2026-11-05 的火山验证只包含合成图片识别及合成会话的祝福生成，没有采集真实微信截图或填写草稿，不扩大此前的真实微信兼容结论。

构建和回归入口见 [README](../README.md)。测试为自定义控制台程序，输出 PASS/FAIL 并通过退出码报告结果；优先使用替身服务和独立数据目录，避免修改个人数据。

### 开发调试记录与正式构建

`AppSettings.DebugMode` 默认关闭。开发客户端在设置中开启并保存后，`DebugSession` 用 `AsyncLocal` 将一个任务的调用链关联到 `AppContext.BaseDirectory/debug/UTC时间-GUID/`。生成任务、独立视觉/UIA检查、图像测试各自建会话，生成历史保存可空的 `DebugDirectory` 以定位对应目录；普通 SQLite 表结构不变。嵌套会话恢复外层，后台模板匹配可继承同一上下文，文件编号与时间线写入有锁保护。

每个目录包含 `manifest.json`、`timeline.jsonl`、带序号的 JSON/TXT/PNG 文件。可记录已有窗口帧、聊天裁剪、选区图、模板分数、模型布局及本地禁点区、点击/滚轮坐标和标注预览；失败在模型坐标解析前发生时仍保留已采集原图和原始模型返回。模型客户端保存请求结构、HTTP状态、脱敏原始响应、提取的模型正文/函数参数、调用耗时及异常，协调器保存重试、解析结果、各阶段和最终结果。请求中的图片 data URL 用引用说明替代，避免与PNG重复保存大段base64。

视觉截图抽查窗口内 35 个采样点，操作前检查实际点击点。若命中窗口的根句柄与目标不一致，或系统没有返回窗口，停止该次视觉操作。开发调试额外保存 `window-point-failed` JSON，包含阶段、检查时间、屏幕及图内坐标、前台句柄、命中句柄和根窗口进程及类名。失败时尝试截取目标窗口的屏幕范围并用红圈标出采样点。截图失败仍记录坐标与窗口信息。该诊断画面仅供本地排查，可能含盖在微信上方的界面。

调试不额外请求模型或执行输入。关闭调试时不额外采集失败画面或转码图像。选区截图在原本的复制与收起选区动作之后才写盘，最终焦点检查和输入之间不插入调试磁盘写入。草稿只记录长度、读取状态与比较结果，不额外导出原剪贴板内容。所有文本先过滤敏感字段及已注册的实际 API Key/加密密钥，认证头不记录，内嵌JSON也脱敏。输出仅允许安全文件名和PNG二进制，每文件32MiB、每任务128MiB；超限或IO失败跳过相关记录并提示诊断不完整，不改变写入/重试决策。调试文件可能含明文聊天画面和模型内容，由用户手动管理，关闭不删除已有记录，目录被忽略且不得分发。

`ProductionMode=true` 通过 `Directory.Build.props` 定义 `WECHAT_DRAFT_PRODUCTION`，使 `DebugSession.IsSupported=false`。正式构建即使读取 `DebugMode=true` 的旧配置也不建目录、不写任何中间记录，设置开关不可启用；正式构建也禁用原最小启动异常文件。普通业务历史不受影响。`build.ps1 -Production -Test -Publish` 输出 `artifacts/production-app`，开发构建保持 `artifacts/app`；正式分发只取干净发布目录，不带用户配置、debug、日志或数据库。

### 多组模型 API 配置

`ModelApiProfile` 仅保存连接字段、DPAPI 加密密钥及各自的截图上传授权，避免嵌套整个应用设置。`AppSettings.ApiProfiles` 保存列表，`ActiveApiProfileId` 使用稳定 ID 标记当前项；顶层连接字段继续作为任务配置快照来源。`ApiProfileSettings` 负责旧配置迁移、命名校验、创建/更新及选择；重命名保留 ID，同名拒绝覆盖，更新使用新列表与不可变配置项，避免编辑污染其他配置。

`LocalRepository.LoadSettings` 将旧单连接设置转为一组默认配置，也兼容早期按名称保存的列表。顶层连接字段仍为当前运行配置，读取时同步到当前配置项，使开发诊断工具保存的新地址或密钥不会被旧列表覆盖；下一次保存时一起加密持久化。

`pack-model-config.ps1` 从源数据库的默认组导出连接字段和 API Key，使用正式软件包 `config/model-config.key` 中的随机 256 位密钥加密。版本标记由 AES-GCM 认证，每次导出生成随机 96 位 nonce，认证标签为 128 位。文件中没有密钥明文、截图授权或工作区数据。软件包与配置文件一并交付给有权使用该凭据的人，接收者持有配套的解密材料。算法参考 [NIST SP 800-38D](https://csrc.nist.gov/pubs/sp/800/38/d/final)。

启动时从 `WechatDraft.exe` 同目录读取 `model-config.wdc`，限制文件大小并校验认证标签及服务地址。成功后用接收者的 DPAPI 保存为默认组，记录加密文件摘要。文件相同或未放置文件时使用本机设置。文件更新时替换默认组并保留其 ID，自定义组及其当前选择保留。载入失败仅提示，保留先前设置。同源的本机授权保留，服务来源变化时清除授权。

生成和发送归档共用截图授权确认。当前组缺少模型名称或 API Key 时提示到「API 管理」配置。配置齐全但当前服务来源尚未授权时，在采集前说明必要截图会上传给当前模型分析，请用户确认。保存前复查活动 API 的 ID 和服务来源，只更新该组的必要截图授权。取消时结束本次操作。任务协调器和模型请求仍会复核授权与服务来源。

「API 管理」为独立导航页（`MainWindow.ApiProfiles`），顶部显示单选列表与“添加 API”；首次读取旧配置时按旧名称「默认 API」找到默认组，并随设置保存其稳定 ID 至 `DefaultApiProfileId`。此后按 ID 识别。默认组只创建名称与选择状态控件，编辑、保存修改与删除入口均限定自定义 API。自定义组显示链接、模型与密钥状态。勾选任意一组立即保存并停止旧的发送归档会话。点“编辑”按 ID 打开该组表单，可修改名称、地址、接口路径、模型、密钥和授权；`Save` 的 `activate:false` 路径不改变 `ActiveApiProfileId`，且保存非使用中组后顶层运行快照恢复为使用中组的值，只有编辑使用中那组时下一次任务使用新值。`EditForm` 生成编辑表单快照，顶层连接字段镜像被编辑组，`ActiveApiProfileId` 仍指向用户勾选的组。新增表单清空连接、密钥和授权，保存后不自动勾选。打开自定义 API 的编辑表单时解密并显示该组密钥。未改动或留空时沿用原密文，输入不同的非空密钥时重新加密。解密失败时显示提示，可重新输入。删除仅允许非使用中的自定义组且至少保留一组；清除密钥按组进行，不能由再次选择恢复该密钥。地址来源变化时清除表单授权，每组的上传授权单独恢复。有未保存编辑时，勾选、编辑、添加或删除前先确认并丢弃未保存内容。切换或编辑只影响后续任务，工作区与其他应用设置保留。
