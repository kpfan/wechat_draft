# 祝语 微信草稿助手

C# + WinUI 3 Windows 桌面原型。打开单聊后按全局快捷键（默认 `Ctrl+Shift+A`），根据所选场景和聊天截图生成中文祝福；预填开启且目标校验通过时，把正文填入输入框。发送始终由用户手动完成。

## 运行

便携构建位于 `artifacts/app/WechatDraft.exe`。整个目录一起保留，双击 EXE，或在项目目录运行：

```powershell
.\run.ps1
```

首次默认进入演示模式，使用虚构联系人「小明」和本地范例，不发起 API 请求，也不操作微信。点击“插入已有草稿”，再点“生成并预填草稿”，可以体验保留原文并直接在文末追加。生成过程中修改演示草稿或切换演示联系人，本次会停止追加。

启动使用普通窗口，不自动最大化；没有保存布局时按显示缩放使用约840×740逻辑像素并居中。正常关闭后记住你调整的普通窗口大小和位置，下次恢复；旧的最大化标记不再生效。切换或移除显示器时限制在可用屏幕内。内容较长时，左侧菜单和主内容均可独立滚动，底部提示不会覆盖菜单。

## Git 版本管理

默认分支为 `main`。源码、测试、内置范例、模板图片、文档和构建脚本纳入版本管理；`.gitignore` 排除本地 SDK、NuGet 缓存、编译与发布产物、个人 `data/` 目录、数据库、截图、日志和密钥文件。上传前用 `git status` 和 `git diff --cached` 检查提交范围。

```powershell
git status
git add .
git diff --cached --stat
git commit -m "Describe the change"
git push origin main
```

新电脑克隆后安装 `global.json` 指定的 .NET 10 SDK，再运行 `build.ps1`；首次启动使用独立的本地配置。原电脑的 DPAPI 加密数据和 API Key 不随 Git 上传，也不能直接作为其他 Windows 用户的配置使用。

### 分发免口令的默认模型配置

在保存有默认模型的原 Windows 用户下执行以下命令。第二条命令默认从 `artifacts/app/data` 读取原配置，将解密文件写入正式软件包的 `config` 目录，并单独生成 `artifacts/model-config.wdc`。

```powershell
.\build.ps1 -Production -Publish
.\pack-model-config.ps1
```

分发整个 `artifacts/production-app` 的程序文件及 `model-config.wdc`。接收者把 `model-config.wdc` 放到 `WechatDraft.exe` 同一目录后启动，程序会自动加载为「默认模型」。首次向新地址上传必要聊天截图时需要确认。其他已选中的自定义 API 会保持选中。更新配置时，使用同一软件包目录再次导出，将新文件交给接收者替换并重启。

软件包的 `config/model-config.key` 必须与配置文件配套。只拿到配置文件的人缺少解密材料。拿到软件和配置文件的人可以解密，因此只发给允许使用该 API Key 的人。发布目录中的 `data/`、`debug/` 和日志属于本机数据，打包时排除它们。

只交付一个绿色压缩包时，把导出的 `model-config.wdc` 放到正式发布目录的 `WechatDraft.exe` 旁，再压缩整个发布目录。接收者完整解压后直接启动 EXE，包内已包含 .NET Desktop Runtime 和默认模型配置。

## 真实微信模式

1. 在「API 管理」选择已配置的「默认模型」，或添加支持图像输入的 Chat Completions 服务。添加自定义 API 时填写服务地址、相对接口路径、模型名称和 API Key。编辑自定义 API 时会显示该组已保存的密钥。只有地址为 `http://localhost`、`http://127.0.0.1` 或 `http://[::1]` 等本机回环地址时才需启用本机 HTTP。远程服务使用 HTTPS。
2. 点击“测试图像能力”。测试只上传自动生成的验证码图片，可能产生模型调用费用。测试图片使用固定分辨率，避免高显示缩放裁掉测试文字。
3. 当前 API 首次用于生成或发送归档时，程序会显示截图上传地址，确认后按当前 API 保存授权。自定义 API 也可在编辑页勾选授权并保存。更换服务来源需重新授权。
   微信识别方式默认“仅视觉”，使用本地模板定位。也可选择“自动 · UIA 优先”或“仅 UIA”。生成及发送核对仍需授权必要的截图。
4. 返回主页，关闭演示模式，手动打开目标单聊。微信窗口列表会自动更新；只有一个窗口时自动选中，多个窗口时手动选择，后续更新保留该选择。
   “检查 UIA 输入框”只检查 UIA，不截图、不调用模型。“检查视觉定位”在本地识别窗口区域并显示预览，不上传整窗、不调用模型、不复制草稿或填写。
5. 点击首页生成按钮或使用快捷键。新配置默认开启“生成后预填到微信输入框”，首页和设置均可关闭，对新任务生效。生成期间可以浏览助手菜单。填写时回到原微信聊天，最多等待 30 秒并受任务总预算限制。程序核对目标后在草稿末尾追加一次，发送由用户手动完成。
   UIA 预填核对聊天面板、标题/输入控件运行期标识和原文。视觉预填由本地 OCR 读取并复查标题，同时核对原窗口实例、几何、输入区和完整原文；按用户选择不依赖模型识别标题或联系人列表。视觉 OCR 标题不是唯一好友 ID，同名或 OCR 误识可能无法区分，仍需检查结果。标题、普通文字或剪贴板无法确认时保留祝福供复制；不自动发送。实际模型以「API 管理」中勾选的配置为准。

视觉预填核对本次 OCR 标题、微信窗口与编辑区后，直接在当前草稿末尾追加祝福，写后读回核对文末。生成期间可以修改或清空草稿。所有预填模式都保留已有空白，不另加换行或空格。

横向和纵向滚轮事件本身不会中断视觉模式的草稿读取或预填。预填仍需核对聊天、输入区域和原文。

首页仅需选择祝福场景，不再单独选择表达语气。模型结合聊天内容、已保存的关系和当次补充要求决定措辞；想要正式、亲切或朴素一些，直接写入“当次补充要求”。旧版保存的语气选项不再影响新任务。

也可以在“当次补充要求”里指定正文长度，例如“写两句”或“写约 150 字”。未指定时由模型根据内容决定长度。

选择“春节”或“元旦”时，可以从十二生肖中选择本次祝福的生肖年。首次默认显示当年的生肖，两种场景共用保存的选择。

所选场景和生肖年用于引导模型生成。正文的场景措辞由你在发送前核对。

不再提供独立的 Emoji 勾选项，需要表情时在“当次补充要求”写“加 1–2 个 Emoji”或指定你想要的数量；也可写“不要使用表情”。模型按补充要求处理，未提及时提示默认不使用。旧版勾选设置不再影响生成。

真实微信首页使用单列布局，生成表单与结果占满内容区，不再常驻显示右侧技术说明。点击“检查视觉定位”并通过后才展开定位预览，可随时收起；演示模式仍保留右侧模拟聊天。

微信窗口列表在进入首页、切回助手、启动生成或检查前以及任务结束后自动更新，无需点击刷新，不做空闲定时刷新。列表展开或任务进行时暂停更新，生成/检查期间锁定目标选择；自动刷新仅查询窗口与进程信息，不截图、不聚焦微信、不调用模型。

生成或检查期间，左侧导航保持可用，可查看历史、范例、API 管理或设置。侧边栏显示任务进度，并提供“查看”和“取消”；返回生成页会恢复原任务页，结果不会因换页而丢失，任务也不会被重复启动。进行中的任务固定使用启动时的模型、场景、演示联系人和范例版本，之后保存的配置用于新任务。为避免记录被进行中的任务重新写回，联系人编辑和历史删除暂时等任务结束；API 图像测试也不与当前任务争用请求。UIA 只允许原微信窗口与当前“祝语”主窗口之间切换，不把浏览助手误报为换聊天；实际截图和填写仍要求原微信在前台。在助手中不自动滚动微信，也不抢占窗口。

历史页在后台分页读取、解密和搜索，输入停顿约 250 毫秒后才筛选，同一页面复用已读记录，不逐字重读数据库。列表使用虚拟化控件，提供首页、上一页和下一页，默认每页 40 条，可选 20 / 40 / 80 条；切页替换当前列表，详情按需展开。关键词可与联系人、场景、预填状态、开始/结束日期和真实/演示模式组合筛选，条件改变回到第一页，可一键重置；日期按本地生成开始日期计算并包含起止当天。总数及总页数在扫描完成后显示，首次打开不为统计总数解密全部历史。搜索覆盖当前工作区的较早记录，不再局限最近 100 条；很旧或无匹配的首次搜索仍需后台扫描加密记录。离开页面取消查询并释放页面缓存，旧搜索结果不会覆盖新关键词。点击“刷新”、删除记录或生成任务结束时更新数据；不会创建明文搜索索引或修改既有历史内容。

称呼应来自聊天消息中“你如何称呼对方”，标题、备注和昵称只用于匹配档案，不直接作为称呼。例如你发出的消息中出现“陈老师，最近还好吗？”，才可据此生成“陈老师，新年快乐！”。模型新推断的称呼须附上你发出的消息摘录和截图编号；不能使用对方称呼你的词、引用或转发内容。档案与历史页显示称呼来源及摘录，供你核对。没有依据时生成中性祝福。

来源不明的旧称呼保留但暂停复用，直到有新的聊天依据或你确认；有聊天依据的称呼可以复用。你仍可在“联系人档案 → 编辑档案”主动填写或确认称呼。已确认且留空的称呼仍保留为空。漏写称呼、来源或消息依据不合格时，使用本任务既有的一次额外请求额度，仍失败则不填写。消息来源和方向依赖模型识别，本地校验不等于独立验证截图文字，须核对展示的消息依据。

历史祝福和已存称呼的完整证据摘录保留在本地。每次生成使用当前消息区截图、所选场景、补充要求、已验证称呼及范例。预填资格由正文校验和当前会话状态决定。

自动模式在 UIA 缺少必要控件或初始枚举超时时进入本地视觉适配器。双工具栏模板及本地边线定位区域，Windows OCR 读取完整标题。生成截图只包含原尺寸消息区，标题和用于匹配的备注名留在本地。开启预填时，生成后复查 OCR 标题、原窗口和编辑区，只在文末粘贴一次并核对结果。预填关闭时只生成。

软件在首次识别标题时创建默认 Windows OCR 引擎，随后在同一个进程内跨任务复用，直到软件退出。标题图片和识别结果按任务缓存。

视觉模式在文末粘贴前取一帧作为对照。粘贴后观察画面变化并稳定，再全选复制并收起选区。祝福留在剪贴板上，直到微信用新复制的内容替换它。画面等待最多 500ms，复制响应窗口最多 150ms。只核对新复制的文本是否以祝福结尾，无法读回时提示检查结果。

调试模式可以记录生成期间的输入面板差异。修饰键或输入法组合未释放时提示用户处理。标题图片完全相同时可在当前任务内复用 OCR 结果，图片变化时重新识别。

写前截图的两处工具栏裁剪逐像素一致，且重新找到的输入分界线与初次定位相同，就沿用本次任务的编辑区坐标。任一条件变化时重新匹配完整布局。调试日志分别记录布局复查、剪贴板备份，以及读回时点击、快捷键和复制响应的耗时。

“检查视觉定位”只检查本地几何，无需 API 或 OCR，不复制或填写。黄框为模板、蓝框为聊天和标题、绿框为消息、紫框为输入面板、橙框为编辑区、红框为发送区域。正式视觉任务用本地 OCR 读取标题，末尾配对中英文括号人数大于 2 时按群聊拒绝；人数中的 OCR 分隔空白和全角数字也参与检查，例如“（1 12）”按 112 人处理。仅人数判断作此归一化，原始标题仍用于精确会话核对。可独立读取的群聊标题还会在协调器进入联系人、历史及模型请求前统一拦截。生成模型只理解消息及生成正文，OCR 模式的模型标题字段不参与当前聊天判断。

已移植 `wechat_vision` 的 DPI 双模板定位思路，以 C# 执行，无需 Python 或 OpenCV。支持当前工具栏在编辑区底部以及较早版本工具栏在上方的布局；输入区分界来自本地边线，不使用“工具栏底部加100像素”的候选点。内置深色模板不承诺兼容其他主题或微信版本，低分、歧义或找不到边界时须调整窗口或使用 UIA。

聊天图片或气泡贴近分界线时，程序会核对输入框一侧的亮度。消息遮住较多对比区域时，还会用输入框两侧圆角和竖边确认横线的位置。证据能指向同一条边线时继续定位。

已同步 `wechat_vision_v0.7z` 的窗口裁剪与坐标换算更新：模板只匹配所选微信窗口客户区，预览使用窗口内坐标，实际操作统一加上该客户区的屏幕偏移，不重复乘显示缩放。截图尺寸不符时停止；需要继续操作微信时，窗口移动/变形或 DPI 改变也会停止并要求重新定位。只生成已固定的画面不再使用实时窗口坐标。更新包的两张图标模板与原版一致，无需替换。

剪贴板里的图片和网页文字由程序备份恢复。微信复制出图片或附件格式时停止追加。当前草稿无法读取且输入区无法确认为空时，结果保留在助手里。

剪贴板里的普通文件复制也可以备份。带文件描述的复制项须有有效路径列表，且所有附带格式都能独立恢复。带文件描述的剪切、流式附件及其他无法完整恢复的组合会停止预填。

本机微信 `4.1.15.56` 曾通过 UIA 真实预填；2026-11-05 同版本也出现无法读取内部控件的状态。新视觉路径已实现，但不能把旧 UIA 成功记录当成新路径实测证据。当前范围见 [实测记录](docs/real-mode-verification.md)。

2026-11-05 早期火山验证仅使用隔离配置；随后按用户明确指令将正式客户端切换为火山方舟 `doubao-seed-2.1-lite`，再次通过合成图片、祝福和布局选区测试，已重启加载。切换及开发验证未操作微信草稿。测试使用 Agent Plan 专属接口；该套餐对非 AI 工具的直接调用有[使用限制](https://docs.volcengine.com/docs/ark/agent-plan-personal-plan-overview?lang=zh)，本地测试通过不证明套餐适用于后续产品分发或生产部署，持续使用应遵守对应套餐规则。配置和验证细节见[实现文档](docs/implementation.md)。

## 发送后保存实际祝福

真实微信首页提供“发送后自动保存祝福”。选好微信窗口后开启归档，首次使用当前 API 时按弹窗确认截图上传地址。本地模板定位及 OCR 读取标题不上传整窗；随后手动发送时，只上传发送前后的标题和消息截图核对最终文字。支持生成后改写和完全自写，不要求先运行生成任务。

本次只监听开启时的聊天。切换聊天、移动/缩放微信窗口或检测到遮挡时停止，需重新开启；暂时切回助手时不采集微信。按键发送以点击过编辑区后的 Enter / Ctrl+Enter 为线索，鼠标发送要求在已定位发送区域内完成按下和释放。没有画面变化不请求模型；多条快速发送、持续变化、方向或正文不明确时保留“待确认”，不猜测、不重试微信动作。

“已发送祝福”展示最终正文、联系人、观察时间和状态，支持搜索、复制、人工核对修正、删除及按当前工作区清空。原始生成历史独立保留；“已记录”不表示对方已收到或已读。演示模式可在右侧自己写入文字，点“模拟发送并归档”验证，不发送微信消息或调用 API。

发送归档开启时本地定位并读取 OCR 标题，不请求布局模型；每次有变化且可核对的发送线索，使用前后标题/消息截图作一次内容核对请求。归档仍独立检查普通单聊与新增文字，不操作剪贴板、不填写或发送；只在用户主动开启期间运行，重启不自动恢复。

## 已实现

- WinUI 3 七个页面：生成、历史、已发送祝福、联系人、范例、API 管理、设置；托盘入口与可修改的全局快捷键。在设置页点「录制快捷键」，在弹窗中按下所需组合，例如 `Ctrl + Shift + B`、`Alt + 7` 或 `F9`，然后保存。字母和数字需搭配 Ctrl、Alt、Shift、Win 中至少一个修饰键，F1–F11 可单独使用。
- 演示模式、真实多模态请求、图像能力测试、API 配置和服务域名授权。
- 生成前采集最多三张消息区截图，一起提交。视觉模式根据已定位的输入区分界线和右边界推算底部滚动条位置，单击一次后按三次 Page Down。画面稳定后保存第一张图，再用 Page Up 向上翻最多两次。每次上翻立即截图，画面尚未变化时在约 220ms 的预算内重拍。视觉采集时切到祝语窗口，最多等待 10 秒返回原聊天。无法安全补图时使用已有截图。视觉翻页后会保留当前浏览位置。
- 既有文本保留、文末直接追加、结果核对、重复触发保护、写入意图持久化和崩溃恢复标记。
- 微信 4.x Qt 输入框通过 UIA 文本接口读回、追加完整预期内容，不产生 Enter 按键；标题截图另提供放大区域，识别不一致则停止写入。
- 自动视觉兜底、强制视觉模式、本地布局与 OCR 标题识别。预填开关同时控制 UIA 和视觉路径；视觉须完成本地标题与全文核对，未知状态只保留生成结果。历史记录生成/布局请求及兜底原因，视觉布局请求始终为 0。
- 智谱 GLM-4.6V 使用数据函数返回结构化结果并关闭推理。限流时退避，额度和权限错误直接提示。
- SQLite 记录联系人与历史；敏感 JSON 载荷及 API Key 由当前 Windows 用户 DPAPI 加密。
- 联系人候选与人工确认、历史搜索与清理。
- 祝福范例支持关键词和状态查询、新增、编辑、删除与启停；保存前校验唯一 ID、场景、关系、字数和 `{称呼}` 占位符，并原子写入 JSON。首次修改内置库时在数据目录的 `examples/` 下创建副本，内置原文件不变；选择的自定义 JSON 在原文件保存。允许删除至空库，空库时仍可生成，只是不向模型提供范例。
- 按当前聊天备注复用当前账号分组内的真实联系人档案；兼容旧档案的显示名，连续生成复用同一档案 ID。历史页标记是否复用了档案。

## 原型限制

- 真实微信版本需要逐项实测。不支持的界面不会尝试坐标盲点或全选覆盖。
- 当前按用户指定规则把聊天标题作为备注匹配名，去除首尾空白后精确查找备注或旧显示名。同账号分组内同名按同一联系人复用；多个匹配时，依次优先人工确认、备注字段匹配、最近更新。历史重复记录不会自动删除，模型只补齐未确认档案的空白或未知字段。
- 视觉截图取自前台且无遮挡的微信窗口。开启预填时，实际读写前核对当前会话、窗口和编辑区，无法读回时提示检查结果。截图默认在内存处理，开发调试可以保存副本。
- 本地视觉定位请求为 0，标题后缀人数判断由本地代码执行；生成及归档仅上传标题和消息裁剪。OCR 可通过 `IChatTitleOcr` 更换，默认 Windows 自带中文 OCR。同一行分段可合并，无文字结果会裁边放大重试；英文大小写、Emoji、符号仍可能误识。OCR 和标题匹配不构成唯一身份保证；实际兼容范围见验证记录。
- UIA 预填允许移动鼠标、点击、滚轮、不改动草稿的按键及浏览当前“祝语”主窗口。实际修改微信草稿（即使之后改回原文）、切换聊天或转到其他程序仍停止；等待返回微信超时后保留正文供复制，不在之后重新获得焦点时补写。写前等待短暂的操作间隙，焦点在另一个输入框时不抢占输入。检测到用户滚动后，不再自动补充上滚，也不恢复旧的消息位置。优先复查右侧聊天页面、聊天标题容器、标题及输入控件的运行期标识，左侧选中项滚出列表不再直接阻止预填；面板或控件被替换仍停止。旧布局无法绑定面板时继续要求唯一选中项。这些标识不是永久微信好友 ID，也不能消除所有界面竞态。原剪贴板支持常见图片、HTML/RTF 及多格式文字的内存备份与恢复，期间新复制的内容不会被覆盖。剪贴板含虚拟文件、无法备份的应用对象或过大数据时，通过目标核对后改用直接输入，保留原剪贴板。视觉模式下需手动核对直接输入的结果。
- 源码不预置模型密钥。本机配置由当前 Windows 用户的 DPAPI 加密；历史与密钥所在的 `data` 目录属于个人数据，不应随程序分发。
- 便携版数据保存在 EXE 旁的 `data` 目录；DPAPI 数据仅能由同一 Windows 用户解密。正式安装版可改为用户应用数据目录。
- 正文使用单个自然段，模型服务参数暂按协议固定。更多厂商协议和高级生成参数可继续扩展。

## 构建与验证

调试开发时，在设置中开启“调试模式”并保存。每次生成、定位检查和图像测试会在程序旁的 `debug/` 下建立独立目录，保存中间截图、模型请求摘要、原始返回、布局及失败日志；历史中的“查看调试记录”可直接打开对应目录。API Key 和认证信息会脱敏。文件可能含联系人、聊天和草稿画面，关闭开关只停止后续记录，已有文件由用户手动清理；不要随程序分发这些文件。

输入区变化被拦截时，调试目录会另存比较基线、变化后图像及差异位置。复制期间的键鼠拦截会区分点击、滚轮或键盘类别；前台拦截记录窗口句柄、进程名与所属关系，不记录按键内容或其他程序画面，便于区分实际操作与界面误判。

按用户请求查看 UIA 边界时，可使用诊断工具的 `uia-regions <输出目录> [窗口句柄]`，导出当前微信窗口的区域标注 PNG 和坐标 JSON。目标须完整显示在前台；只有一个微信窗口时自动使用，否则须指定句柄。图中区分实际 UIA 标题/编辑控件与程序计算的聊天截图范围，未找到唯一滚动控件时明确标注。此命令不调用模型、不点击、复制、滚动或修改输入框；仅显式导图时将包含聊天画面的图片写入指定目录，不改变普通 UIA 检查的无截图行为。

正式版本使用 `./build.ps1 -Test -Publish -Production`，输出到 `artifacts/production-app/`。该版本在构建时强制禁用调试保存，即使复制了开启调试的旧设置也不会生成中间截图或模型日志；常规加密业务历史仍按正常设置保存。普通开发构建默认也关闭调试，供需要时在界面开启。

需要 Windows x64、.NET 10 SDK。项目优先使用 `.tools/dotnet/dotnet.exe`，否则使用系统 SDK。

```powershell
.\build.ps1 -Test -Publish
```

依赖来自 NuGet 官方源或微软维护的 dotnet-public 镜像，包缓存限制在项目 `.nuget` 目录。若 `.tools/feed` 已收集离线依赖，构建脚本优先使用该目录。发布目录包含 Windows App SDK 运行时。正式发布也包含 .NET Desktop Runtime，启动时直接使用 EXE 同目录的运行时。开发发布通过本地 SDK 或已安装的 .NET 10 Desktop Runtime 运行。

验证程序覆盖追加规则、Emoji 字数及旧表情开关不干扰补充要求、输出校验、服务地址、加密数据、账号隔离、范例回退、截图滚动上限、编辑冲突、并发触发、取消、写入不重试和崩溃标记。运行：

```powershell
.\.tools\dotnet\dotnet.exe run --project tests/WechatDraft.Tests -c Release
```

需要验证实际 Windows 剪贴板时，单独运行 `.\.tools\dotnet\dotnet.exe run --project tests/WechatDraft.Tests -c Release -- --native-clipboard`。它先备份当前剪贴板，再暂放合成文字和图片，结束时恢复；检测到外部新复制则保留新内容并停止。此检查不操作微信、不调用模型。

## 项目结构

| 路径 | 内容 |
| --- | --- |
| `src/WechatDraft.App` | WinUI 3 界面及演示适配器 |
| `src/WechatDraft.Core` | 模型协议、任务编排、数据、范例和正文规则 |
| `src/WechatDraft.Windows` | DPAPI、快捷键、窗口识别、截图、UIA 与受保护粘贴 |
| `tests/WechatDraft.Tests` | 可执行验证程序 |
| `config/blessing_examples.json` | 内置范例源文件 |
| `docs/requirements.md` | 需求文档 |

更新内置范例源文件后需要重新构建，或者在客户端直接选择该 JSON 文件后重载。

模型服务在「API 管理」页面维护。已保存的每组配置单独成卡片，勾选哪个就使用哪个，当前项标记“使用中”，选择立即保存并在重启后保留。原有「默认 API」以「默认模型」显示，仅供选择使用。点自定义 API 的“编辑”可以修改名称、地址、接口路径、模型、密钥和授权。保存编辑不改变勾选的使用中配置，修改“使用中”那组则下一次任务直接使用新值。新配置点“＋ 添加 API”创建，保存后需自行勾选启用；新增配置不继承其他配置的密钥或授权。自定义 API 可测试图像能力、清除密钥或删除。至少保留一组，且不能删除“使用中”的那组。有未保存修改时，勾选、编辑、添加或删除前会提示确认。
